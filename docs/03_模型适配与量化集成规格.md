# 模型适配与量化集成规格

> 版本：v0.2 ｜ 原则：运行时/量化路线均需实测验证

## 1. 接入优先级

| 模型 | 阶段 | 角色 | CPU 运行时候选 | 备注 |
|---|---|---|---|---|
| Dummy | MVP | 测试基座 | NumPy | 无模型依赖 |
| Piper | MVP | 超轻量 baseline | Piper/ONNX | 优先完成 |
| Kokoro | MVP | 轻量质量基准 | ONNX Runtime / 官方支持路径 | 优先完成 |
| Qwen3-TTS 0.6B | MVP-Experimental | 较大模型量化验证 | 官方/社区可用 CPU 路线 | 可 feature flag |
| CosyVoice 2 | Batch 2 | 克隆/流式候选 | 官方支持路径 / ONNX/JIT 候选 | 主链路稳定后接入 |
| MeloTTS | Batch 2 | 经典 baseline | PyTorch CPU | 主链路稳定后接入 |
| Fish Speech | Phase 2 | 扩展候选 | 待验证 | 不阻塞 MVP |

> 不在规格中承诺某一社区量化格式必然兼容。具体 runtime、模型版本、license、下载源和量化方式在 Adapter 实现 PR 中锁定。

## 2. Capability Matrix

每个 Adapter 至少声明以下字段：

```yaml
capabilities:
  streaming: false
  seed: false
  speed: true
  voices: true
  voice_clone: false
  languages: [zh, en]
```

运行时能力表由实际 Adapter 决定，文档只给预期：

| 模型 | Streaming | Seed | Speed | Multi-voice | Voice Clone |
|---|---:|---:|---:|---:|---:|
| Dummy | 可模拟 | 是 | 是 | 是 | 否 |
| Piper | 是（当前 Python API 按句输出 chunk） | 否 | 是 | 是 | 否 |
| Kokoro | 否（当前 Adapter） | 否 | 是 | 是（当前直接文本仅英美/英式英语 voice） | 否 |
| Qwen3-TTS 0.6B placeholder | 否 | 否 | 否 | 否 | 否 |
| CosyVoice 2 | 待 Adapter 验证 | 待验证 | 待验证 | 是 | 候选 |
| MeloTTS | 通常否 | 否 | 是 | 是 | 否 |

## 3. Adapter 验收契约

每个真实模型必须通过：

1. `load_model()` 可重复调用或给出明确状态错误。
2. `infer()` 返回非空 `float32` mono audio + sample rate。
3. `unload_model()` 后释放主要模型引用。
4. 不支持 streaming 时 `infer_stream()` 明确抛出 `NotImplementedError`，并在 capability 中标记 false。
5. 不把 RTF/RSS 等统一指标写死在 Adapter 内。
6. 记录 `model_version`、`runtime`、`quantization` 供报告导出。

## 4. CPU 优化策略

优先级从高到低：

1. 控制 OMP/MKL/PyTorch/ONNX Runtime 线程数。
2. 使用模型官方支持的 CPU runtime。
3. 对支持的模型评估 ONNX INT8 / 低位权重等量化方式。
4. 大模型使用 lazy load + 互斥常驻。
5. affinity 仅在平台支持时启用。

### 4.1 性能目标记录方式

不再在模型表中写固定“预期 RTF”。实测结果写入 Benchmark 报告：

```json
{
  "model_id": "kokoro-82m",
  "model_version": "...",
  "runtime": "onnxruntime",
  "quantization": "fp32",
  "cpu": "...",
  "threads": 4,
  "rtf": 0.0,
  "peak_rss_mb": 0.0
}
```

## 6. 暂缓决策

以下内容不在 Stage 0/1 固化：

- Qwen3-TTS 的最终 CPU runtime/量化格式。
- CosyVoice 的最终 CPU 推理路径与 NFE 优化幅度。
- Fish Speech 接入方式。
- 模型专用独立 venv worker。

这些项以真实 POC 为准，避免文档先行假定实现已经可用。


## 7. Piper 实现冻结（2026-09-03）

- Runtime：`piper-tts>=1.4,<2`，使用 `PiperVoice.load()` + `PiperVoice.synthesize()`。
- 模型格式：`.onnx` + 相邻 `.onnx.json`。目录模式仅允许恰好一个 `.onnx`，避免 voice 选择歧义。
- `speed` 统一语义为“倍率越大越快”，Adapter 映射为 `length_scale = 1 / speed`。
- Multi-speaker voice 使用 `speaker_id_map`；单 speaker 暴露 `default`。
- Streaming capability 标记为 true，但粒度由 Piper 当前 API 决定，为 sentence chunk，不承诺 token/frame 级流式。
- `num_threads` 当前记录为 requested metadata；Piper Python API 未暴露可传入的 ORT `SessionOptions`，实际线程硬限制继续由后续 worker/process 级资源控制完善。
- CI 不把模型加入仓库；真实 smoke 动态下载官方 low-quality voice。


## 8. Kokoro 实现冻结（2026-09-03）

- Runtime：`kokoro-onnx>=0.6.1,<1`，Kokoro v1.0 ONNX。
- CI/弱算力 baseline 优先使用官方 `kokoro-v1.0.int8.onnx`（约 88 MB）+ `voices-v1.0.bin`。
- Adapter 自建 ONNX Runtime `InferenceSession`，`intra_op_num_threads=num_threads`，CPU provider only。
- 当前 `speed` 按 runtime 实际约束冻结为 `0.5~2.0`。
- Runtime 虽提供 async `create_stream()`，当前统一 Adapter 的同步 streaming 契约尚未桥接，因此 capability 暂标 false，不伪造 TTFB。
- 当前直接文本先只声明 `en-us` / `en-gb`。模型本身包含更多语言 voice，但部分语言推荐独立 Misaki/G2P 路线，完成验证后再扩 capability。
- `kokoro-onnx` 为 MIT；Kokoro 模型权重为 Apache-2.0。


## 9. Qwen3-TTS experimental 冻结（2026-09-03）

- 上游 0.6B 模型存在，但 EdgeTTS-Arena **尚未批准任何 CPU runtime/量化格式**。
- 当前 `Qwen3TTSAdapter` 是显式 placeholder：默认 disabled + experimental；`load_model()` 返回 `experimental_runtime_unavailable`，不生成假音频。
- capability 只描述当前 Adapter 已实现能力，因此 streaming/seed/speed/voices/voice_clone 均为 false，languages 为空；不把上游模型潜在能力当作本项目已经支持。
- 2026-07 已出现社区 ncnn/C++ CPU FP32 移植并公开一致性验证，但它们仍属于社区 POC，不等同于本项目稳定 runtime。
- 转正式 Adapter 前至少需要：固定 upstream/model revision、可重复转换/资产校验、CPU 内存/RTF 基准、许可证与再分发审查、跨平台 smoke test。
- TODO(Stage 6/POC)：比较官方 Python CPU 路线、ncnn/C++ 以及其他可复现量化路线，再冻结一个 runtime。
