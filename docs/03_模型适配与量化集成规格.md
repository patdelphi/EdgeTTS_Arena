# 模型适配与量化集成规格

> 版本：v0.3 ｜ 原则：运行时/量化路线均需实测验证

## 1. 接入优先级

| 模型 | 阶段 | 角色 | CPU 运行时 | 当前状态 |
|---|---|---|---|---|
| Dummy | MVP | 测试基座 | NumPy | ✅ |
| Piper | MVP | 超轻量 baseline | Piper/ONNX | ✅ real CPU |
| Kokoro | MVP | 轻量质量基准 | ONNX Runtime | ✅ int8 real CPU |
| Qwen3-TTS 0.6B | MVP-Experimental | 较大模型量化验证 | 待批准 | placeholder |
| CosyVoice 300M SFT | Batch 2 | SFT/流式候选 | 官方 QwenAudio/CosyVoice CPU 路线 | ✅ 独立 real CPU gate，仍 experimental/disabled |
| MeloTTS | Batch 2 | 经典 baseline | PyTorch CPU | ✅ 独立 real CPU gate，仍 experimental/disabled |
| Fish Speech | Phase 2 | 扩展候选 | 待验证 | 未开始 |

> 不在规格中承诺某一社区量化格式必然兼容。具体 runtime、模型版本、license、下载源和量化方式必须以本项目真实 gate 为准。

## 2. Capability Matrix

每个 Adapter 至少声明以下字段：

```yaml
capabilities:
  streaming: false
  seed: false
  speed: true
  voices: true
  voice_clone: false
  languages: [zh, en]
```

运行时能力表以当前 Adapter 已实现能力为准：

| 模型 | Streaming | Seed | Speed | Multi-voice | Voice Clone |
|---|---:|---:|---:|---:|---:|
| Dummy | 模拟 | 是 | 是 | 是 | 否 |
| Piper | 是（sentence chunk） | 否 | 是 | 是 | 否 |
| Kokoro | 否（当前同步 Adapter） | 否 | 是 | 是 | 否 |
| Qwen3-TTS 0.6B placeholder | 否 | 否 | 否 | 否 | 否 |
| CosyVoice 300M SFT | 是（runtime chunk） | 否 | 是 | 是 | 否（当前仅 SFT） |
| MeloTTS | 否 | 否 | 是 | 是 | 否 |

## 3. Adapter 验收契约

每个真实模型必须通过：

1. `load_model()` 可重复调用或给出明确状态错误。
2. `infer()` 返回非空 `float32` mono audio + sample rate。
3. `unload_model()` 后释放主要模型引用。
4. 不支持 streaming 时 `infer_stream()` 明确抛出 `NotImplementedError`，并在 capability 中标记 false。
5. 不把 RTF/RSS 等统一指标写死在 Adapter 内。
6. 记录 `model_version`、`runtime`、`quantization` 供报告导出。
7. 模型资产与前处理资产必须显式可定位；推理阶段不得通过“缺文件就偷偷联网”掩盖部署缺失。

## 4. CPU 优化策略

优先级从高到低：

1. 控制 OMP/MKL/PyTorch/ONNX Runtime 线程数。
2. 使用模型官方支持的 CPU runtime。
3. 对支持的模型评估 ONNX INT8 / 低位权重等量化方式。
4. 大模型使用 lazy load + 进程/worker 隔离。
5. affinity/cgroup 仅作为 best-effort 资源约束，不假设宿主机逻辑核数等于容器可用核数。

### 4.1 性能目标记录方式

不在模型表中写固定“预期 RTF”。实测结果写入 Benchmark 或 gate report：

```json
{
  "model_id": "kokoro",
  "model_version": "...",
  "runtime": "onnxruntime",
  "quantization": "int8",
  "cpu": "...",
  "threads": 4,
  "rtf": 0.0,
  "peak_rss_mb": 0.0
}
```

## 5. 模型配置示例

```yaml
models:
  - id: piper
    enabled: true
    adapter: piper
    model_path: ./models/piper
    keep_in_memory: false
    num_threads: 4

  - id: qwen3-tts-0.6b
    enabled: false
    experimental: true
    adapter: qwen3
    model_path: ./models/qwen3-tts-0.6b
    num_threads: 4
```

默认 `config/models_config.yaml` 中只有 Dummy 启用。Piper/Kokoro 下载资产后可在本地手动设为 `enabled: true`。CosyVoice/MeloTTS 即使已通过独立 real CPU gate，当前仍保留 `experimental: true`、`enabled: false`。

## 6. 暂缓决策

- Qwen3-TTS 的最终 CPU runtime/量化格式。
- Fish Speech 接入方式。
- CosyVoice/MeloTTS 正式模型专用 worker/venv 与主 Arena UI 的统一生命周期管理。
- 真实 ARM/弱算力设备上的模型选择与默认线程预算。

这些项以真实 POC 为准，避免文档先行假定实现已经可用。

## 7. Piper 实现冻结（2026-09-03）

- Runtime：`piper-tts>=1.4,<2`，使用 `PiperVoice.load()` + `PiperVoice.synthesize()`。
- 模型格式：`.onnx` + 相邻 `.onnx.json`。
- `speed` 统一语义为“倍率越大越快”，Adapter 映射为 `length_scale = 1 / speed`。
- Multi-speaker voice 使用 `speaker_id_map`；单 speaker 暴露 `default`。
- Streaming capability 为 sentence chunk，不承诺 token/frame 级流式。
- CI 使用真实 `en_US-lessac-low` voice 完成 CPU gate。

## 8. Kokoro 实现冻结（2026-09-03）

- Runtime：`kokoro-onnx>=0.6.1,<1`，Kokoro v1.0 ONNX。
- CI/弱算力 baseline 使用 `kokoro-v1.0.int8.onnx` + `voices-v1.0.bin`。
- Adapter 自建 ONNX Runtime `InferenceSession`，CPU provider only。
- `speed` 按 runtime 实际约束冻结为 `0.5~2.0`。
- 当前统一同步 streaming 契约尚未桥接，因此 capability 暂标 false，不伪造 TTFB。
- 当前直接文本声明 `en-us` / `en-gb`；更多语言待 G2P/voice 路线验证后再扩。

## 9. Qwen3-TTS experimental 冻结（2026-09-03）

- 当前 `Qwen3TTSAdapter` 是显式 placeholder：默认 disabled + experimental。
- `load_model()` 返回 `experimental_runtime_unavailable`，不生成假音频。
- 转正式前至少需要：固定 upstream/model revision、可重复转换/资产校验、CPU RAM/RTF、license 与跨平台 smoke。

## 10. CosyVoice 300M SFT 实现冻结（2026-09-03）

- Upstream：QwenAudio/CosyVoice pinned source，当前 Adapter 走 `AutoModel + inference_sft()`。
- 当前只接 SFT speaker 模式，不把 zero-shot prompt audio/text 强行映射为 voice id。
- 独立 real CPU gate：Ubuntu 24.04 / Python 3.10 / 2 threads，通过真实 WAV + JSON metrics + audio sanity。
- 单次 gate：4.098s audio、17.875s inference、RTF 4.362、peak RSS 4181 MB；仅作追溯。
- `wetext==0.0.4` 所需 5 个 FST 由 `scripts/prepare_cosyvoice_frontend.py` 显式准备并生成 SHA-256 manifest。
- offline preflight 会禁止 `snapshot_download()` 再执行 Adapter load；该 gate 已通过。
- 官方 pinned requirements 与主 Arena UI 依赖存在版本冲突风险，因此继续 `experimental + disabled`，正式 UI 集成前必须进入独立 worker/venv。

## 11. MeloTTS 实现冻结（2026-09-03）

- Runtime：官方 `melo.api.TTS` + PyTorch CPU。
- 支持 EN/ES/FR/ZH/JP/KR、speaker id 与 speed。
- Adapter 要求本地 `model.json` 显式指向 config/checkpoint，不允许推理时隐式 HuggingFace 下载。
- 独立 real CPU gate 已通过；历史单次记录 4.415s audio、8.005s inference、RTF 1.813、peak RSS 2960.8 MB，仅作追溯。
- 继续 `experimental + disabled`，待独立 worker/venv 正式集成。
