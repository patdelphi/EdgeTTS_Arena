# 接口协议与数据规范

> 版本：API v1.0 Draft 3 ｜ Stage 3 实现基线 ｜ MVP 同步接口

## 1. 通用约定

Base path：`/api/v1`

成功 envelope：

```json
{"code": 200, "message": "success", "data": {}, "error": null}
```

失败 envelope：

```json
{
  "code": 1001,
  "message": "invalid request",
  "data": null,
  "error": {"type": "validation_error", "details": []}
}
```

- HTTP 状态码表达传输/系统级结果。
- `code` 表达应用错误码。
- 时间戳使用 UTC ISO 8601。
- 所有音频指标统一使用 ms / MB / percent。
- 输入文本默认最大 1000 字符，并拒绝非法控制字符。
- 本地健康检查：`GET /healthz`。
- OpenAPI：`/docs` / `/redoc`。

## 3. 同步 Arena Benchmark

### `POST /api/v1/benchmark/run`

MVP 中该接口**同步执行并返回最终结果**。`run_id` 是归档 ID，不代表后台 job。FastAPI handler 使用线程 offload，避免阻塞 ASGI event loop，但 API 语义仍然是同步请求/最终响应。

Request：

```json
{
  "text": "随着大模型向端侧迁移……",
  "models": ["piper", "kokoro"],
  "execution_mode": "sequential",
  "cpu_threads_per_model": 4,
  "config": {
    "voice": null,
    "speed": 1.0,
    "seed": null,
    "sample_rate": null
  }
}
```

字段约束：

- `models`：1~4 个，且不得重复。
- `execution_mode`：`sequential | concurrent`；默认 Sequential。
- `cpu_threads_per_model`：默认 4，实际值经 ResourceGuard/CPU core clamp。
- `seed` 默认 `null`；仅 capability 支持时传入。显式提供但模型不支持时记录 warning，不阻塞其他模型。
- `sample_rate` 目前不做 resample；显式提供时记录 warning 并保留模型原生采样率。
- voice/speed 与模型能力冲突时，该模型结果返回 `1003 capability_conflict`。
- 单模型失败不使整轮 benchmark 失败，其他模型继续执行。

Response：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "run_id": "run_20260903_101822_ab12cd",
    "started_at": "2026-09-03T10:18:22.000Z",
    "completed_at": "2026-09-03T10:18:28.000Z",
    "execution_mode": "sequential",
    "cpu_threads_per_model": 4,
    "results": [
      {
        "model_id": "kokoro",
        "status": "success",
        "audio_url": "/api/v1/audio/download/run_.../kokoro.wav",
        "metrics": {
          "inference_time_ms": 420.5,
          "audio_duration_ms": 3800.0,
          "rtf": 0.111,
          "ttfb_ms": null,
          "peak_rss_mb": 342.1,
          "rss_delta_mb": 64.5,
          "avg_cpu_usage_pct": 36.2
        },
        "warnings": [],
        "error": null,
        "metadata": {
          "runtime": "kokoro-onnx",
          "model_version": "v1.0",
          "quantization": "int8"
        }
      }
    ]
  },
  "error": null
}
```

单模型失败：

```json
{
  "model_id": "qwen3-tts-0.6b",
  "status": "error",
  "audio_url": null,
  "metrics": null,
  "warnings": [],
  "error": {"code": 1002, "type": "model_unavailable", "message": "model is unavailable"},
  "metadata": null

```

### 3.1 Run 落盘结构

```text
exports/<run_id>/
  audio/
    <model_id>.wav
  benchmark_report.json
  environment.json
```

`benchmark_report.json` 保存本轮请求参数、最终结果及 per-model metadata；`environment.json` 保存运行环境快照。

## 4. Audio Download

### `GET /api/v1/audio/download/{run_id}/{filename}`

- 仅允许访问 `exports/<run_id>/audio/` 下的安全 `.wav` basename。
- `run_id` / `filename` 均做 allow-list 校验。
- 禁止 `..`、绝对路径和任意本地文件读取。
- Content-Type：`audio/wav`。
- 返回 `X-Content-Type-Options: nosniff`。

## 5. Streaming

### `WS /api/v1/tts/stream?model=<model_id>`

仅当模型可用且 `capabilities.streaming=true` 时开放；不支持模型返回 `1003 capability_conflict` 并关闭连接。

客户端 start event：

```json
{"action":"start","text":"你好，这里是流式测试。","voice":null,"speed":1.0}
```

服务端顺序：

1. JSON `started` event。
2. 第一个可播放 chunk 准备完成后发送 `first_chunk`。
3. 二进制 `pcm_s16le` chunk。
4. 后续二进制 chunk。
5. JSON `complete`。

```json
{"event":"first_chunk","ttfb_ms":320.0,"chunk_idx":0,"sample_rate":24000,"encoding":"pcm_s16le"}
```

```json
{"event":"complete","audio_duration_ms":2100.0,"rtf":0.58,"chunks":8}
```

非流式 benchmark 的 `ttfb_ms` 必须保持 `null`，不得用整段完成时间伪造 TTFB。

## 6. Export

### `GET /api/v1/export/{run_id}`

按已落盘 run 构建 ZIP：

- `audio/*.wav`
- `benchmark_report.json`
- `environment.json`

run 不存在或归档不完整返回 `1002`。

## 7. 错误码

| 应用码 | HTTP | 含义 |
|---:|---:|---|
| 1001 | 400 | 输入/路径无效 |
| 1002 | 404 | 模型、run 或音频不存在/不可用 |
| 1003 | 409 | 参数与模型 capability 冲突 |
| 2001 | 503 | CPU/系统资源暂不可用 |
| 2002 | 503 | 内存保护触发 |
| 3001 | 504 | 推理超时 |
| 3002 | 500 | 模型推理内部错误 |

## 8. 启动方式

```bash
edgetts-arena serve
```

默认绑定 `127.0.0.1:8000`。显式绑定 `0.0.0.0` / `::` 时日志必须提示网络暴露风险。

## 9. Phase 2 预留
