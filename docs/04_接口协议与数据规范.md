# 接口协议与数据规范

> 版本：API v1.0 Draft 6 ｜ Stage 6 实现基线 ｜ 本地同步接口

## 1. 通用约定

Base path：`/api/v1`。

成功：

```json
{"code":200,"message":"success","data":{},"error":null}
```

失败：

```json
{"code":1001,"message":"invalid request","data":null,"error":{"type":"validation_error","details":[]}}
```

- 时间戳：UTC ISO 8601。
- 指标：ms / MB / percent。
- 文本默认最大 1000 字符并拒绝非法控制字符。
- `GET /healthz` 健康检查；`/docs` / `/redoc` 为 OpenAPI UI。

## 2. 系统与模型

### `GET /api/v1/system/models`

返回 system environment、模型状态、experimental 标识、capabilities、voices，以及 worker 路由状态。模型未真实推理前 runtime/version/quantization 可为 `unknown`；真实 benchmark 的 `metadata` 必须记录 Adapter 实测信息。

模型 worker 字段：

```json
{
  "id": "cosyvoice-300m-sft",
  "worker_mode": "external",
  "worker_python_configured": true
}
```

- `worker_mode=in_process`：`keep_in_memory=true`，当前进程常驻路径。
- `worker_mode=spawn`：非持久模型使用主 Arena 当前 Python 的 spawn worker。
- `worker_mode=external`：非持久模型通过 `worker_python` / `worker_python_env` 指定的独立 Python/venv 执行。
- `worker_python_configured` 仅表示已解析到专用解释器，不表示真实模型资产一定可用。
- API **不得**返回专用 Python 的本机绝对路径。

System environment 包含：`os_release`、`python_version`、`python_implementation`、`python_executable`、`package_versions`、`thread_settings`、`cpu_effective_cores`、`available_ram_effective_gb`。

## 3. 单轮同步 Benchmark

### `POST /api/v1/benchmark/run`

1~4 模型，同步返回最终结果；`run_id` 是归档 ID，不代表后台 job。

- `execution_mode=sequential|concurrent`，默认 sequential。
- 单模型失败不使整轮失败。
- speed/voice capability 冲突返回 per-model `1003`。
- seed 不支持时记录 warning。
- sample-rate override 当前只记录 warning，保留模型原生采样率。
- 非流式 `ttfb_ms=null`。
- `execution_profile`: Sequential=`baseline`，Concurrent=`pressure`。
- `requested_cpu_threads_per_model`: 用户请求值。
- `cpu_threads_per_model`: ResourceGuard 计算后的有效值。
- `total_threads_budget`: 本轮总线程预算。
- `resource_warnings`: 自动 clamp 等提示。

Concurrent 在执行前检查逻辑核公平分配、最大并发模型数和每模型最低内存预算；预算不足返回 `2001`。

### Isolated worker diagnostics

`keep_in_memory=false` 的 spawn worker 和 external Python worker 都返回可选 `worker`：

```json
{
  "worker": {
    "mode": "external",
    "pid": 12345,
    "exit_code": 0,
    "elapsed_ms": 421.8,
    "termination": "normal",
    "signal": null,
    "oom_suspected": false,
    "runtime": {
      "protocol": "external-json",
      "protocol_version": 1,
      "python_version": "3.10.14",
      "python_implementation": "CPython"
    }
  }
}
```

普通 multiprocessing worker 的 `mode=spawn`，`runtime.protocol=multiprocessing-spawn`；external worker 的 `mode=external`，必须完成 protocol version handshake。

- external worker 当前协议版本为 `1`；版本不匹配返回 `ExternalWorkerProtocolError` 并映射到模型 worker failure 路径，不接受不兼容 payload。
- watchdog timeout：`termination=timeout_terminate|timeout_kill`，错误码 `3001`。
- worker crash / protocol failure：`3002`。
- worker 内显式 `MemoryError`：`2002 worker_memory_error`。
- 无结果且被 `SIGKILL` 终止时只设置 `oom_suspected=true`，不宣称确定 OOM。
- `keep_in_memory=true` 的进程内路径 `worker=null`。
- worker error message / traceback 写入结果前做有界 tail 截断（当前上限 8192 字符），避免第三方 runtime 的超长 stderr 破坏 report/response 体积；保留尾部便于看到最终异常。

external worker 通过 JSON stdin/stdout 协议执行，WAV 写入主进程预先校验的 artifact 路径；主进程只接收小型 metadata/metrics JSON。

## 4. 标准 Benchmark Presets

### `GET /api/v1/benchmark/presets`

```json
{
  "version":"1.0",
  "defaults":{"warmup_runs":1,"measured_runs":3},
  "cases":[
    {"id":"TC-01","name":"日常短交互","text":"...","focus":["latency","pause"]}
  ]
}
```

当前固定 TC-01~TC-05。

## 5. Repeated Benchmark Suite

### `POST /api/v1/benchmark/suite`

用于标准、可复现的重复评测。固定 **Sequential**，不把压力测试数据与纯净横向基准混在一起。

Request：

```json
{
  "models":["piper","kokoro"],
  "case_ids":["TC-01","TC-02","TC-05"],
  "cpu_threads_per_model":4,
  "warmup_runs":1,
  "measured_runs":3,
  "config":{"voice":null,"speed":1.0,"seed":null,"sample_rate":null}
}
```

约束：models 1~4 且唯一；case_ids 可省略；warmup 0~10；measured 1~20。同一 case/model 一次 load 后完成 warm-up + repeats。

Response 每个 case/model 返回：

- `measurements[]`：每次正式测量原始 metrics/error。
- `aggregate`：每个指标 `count/mean/median/min/max/p95/variance`。
- `successful_runs` / `measured_runs`。
- 代表音频 `audio_url`。
- `metadata`：runtime/model_version/quantization 等。
- status：`success | partial | error`。
- `worker`：与单轮相同的 isolated process diagnostics。

若模型配置了 external Python worker，整个 case/model group（warm-up + repeats）在同一个专用解释器子进程中完成。

## 6. Run Artifact

单轮：

```text
exports/<run_id>/
  audio/<model_id>.wav
  benchmark_report.json
  environment.json
```

Suite：

```text
exports/<run_id>/
  audio/<case_id>__<model_id>.wav
  benchmark_report.json
  environment.json
```

Blind Reveal 后可增加 `blind_scores.json`。

## 7. 下载与 Export

### `GET /api/v1/audio/download/{run_id}/{filename}`

只允许安全 `.wav` basename，禁止路径穿越。

### `GET /api/v1/export/{run_id}`

ZIP 包含 `audio/*.wav`、`benchmark_report.json`、`environment.json`、optional `blind_scores.json`。

## 8. Streaming

### `WS /api/v1/tts/stream?model=<model_id>`

仅 `capabilities.streaming=true` 的可用模型开放。首个可播放 `pcm_s16le` chunk 才计 TTFB；非流式 benchmark 不伪造 TTFB。

当前 external Python worker 接入的是同步 BenchmarkService/Suite 路径；不要据此推断跨进程 streaming 已实现。

## 9. 错误码

| 应用码 | HTTP | 含义 |
|---:|---:|---|
| 1001 | 400 | 输入/路径无效 |
| 1002 | 404 | 模型、run、case 或音频不存在/不可用 |
| 1003 | 409 | 参数与 capability 冲突 |
| 2001 | 503 | CPU/系统资源暂不可用 |
| 2002 | 503 | 内存保护触发 |
| 3001 | 504 | 推理超时 |
| 3002 | 500 | 模型推理/worker 内部错误 |

## 10. Worker 配置（非 API）

`config/models_config.yaml` 可使用：

```yaml
worker_python: ""
worker_python_env: EDGETTS_ARENA_COSYVOICE_PYTHON
```

显式 `worker_python` 优先；若为空则读取 `worker_python_env`。主 Arena 默认给 CosyVoice/MeloTTS 声明对应环境变量名。`edgetts-arena doctor --workers` 用于部署前 worker 协议检查。

## 11. Phase 2

长时间压测如需异步语义，再增加 `/jobs` 系列接口；不得改变现有同步 `/benchmark/run` 与 `/benchmark/suite` 的含义。external worker 的跨进程 streaming、worker pool/常驻生命周期与自动 venv bootstrap 属于后续增强。
