# 接口协议与数据规范

> 版本：API v1.0 Draft 4 ｜ Stage 5 实现基线 ｜ 本地同步接口

## 1. 通用约定

Base path：`/api/v1`。

成功：

```json
{"code":200,"message":"success","data":{},"error":null}
```

失败：

```json
{"code":1001,"message":"invalid request","data":null,"error":{"type":"validation_error","details":[]}}
```

- 时间戳：UTC ISO 8601。
- 指标：ms / MB / percent。
- 文本默认最大 1000 字符并拒绝非法控制字符。
- `GET /healthz` 健康检查；`/docs` / `/redoc` 为 OpenAPI UI。

## 2. 系统与模型

### `GET /api/v1/system/models`

返回 system environment、模型状态、experimental 标识、capabilities、voices。模型未真实推理前 runtime/version/quantization 可为 `unknown`；真实 benchmark 的 `metadata` 必须记录 Adapter 实测信息。

Stage 5 的 system environment 增加：

- `os_release`
- `python_version`
- `python_implementation`
- `python_executable`
- `package_versions`
- `thread_settings`

## 3. 单轮同步 Benchmark

### `POST /api/v1/benchmark/run`

保持 Stage 3 语义不变：1~4 模型，同步返回最终结果；`run_id` 是归档 ID，不代表后台 job。

- `execution_mode=sequential|concurrent`，默认 sequential。
- 单模型失败不使整轮失败。
- speed/voice capability 冲突返回 per-model `1003`。
- seed 不支持时记录 warning。
- sample-rate override 当前只记录 warning，保留模型原生采样率。
- 非流式 `ttfb_ms=null`。

Stage 5 开始，`environment.json` 会记录本轮实际 `cpu_threads_per_model`。

## 4. 标准 Benchmark Presets

### `GET /api/v1/benchmark/presets`

返回 `config/benchmark_presets.json` 当前标准题库：

```json
{
  "version":"1.0",
  "defaults":{"warmup_runs":1,"measured_runs":3},
  "cases":[
    {"id":"TC-01","name":"日常短交互","text":"...","focus":["latency","pause"]}
  ]
}
```

当前固定 TC-01~TC-05。

## 5. Repeated Benchmark Suite

### `POST /api/v1/benchmark/suite`

用于标准、可复现的重复评测。Stage 5 固定 **Sequential**，不把压力测试数据与纯净横向基准混在一起。

Request：

```json
{
  "models":["piper","kokoro"],
  "case_ids":["TC-01","TC-02","TC-05"],
  "cpu_threads_per_model":4,
  "warmup_runs":1,
  "measured_runs":3,
  "config":{"voice":null,"speed":1.0,"seed":null,"sample_rate":null}
}
```

约束：

- models：1~4，唯一。
- case_ids：可省略，省略则 TC-01~05 全跑；显式提供时唯一。
- warmup：0~10，默认 preset 配置值。
- measured：1~20，默认 preset 配置值。
- 同一 case/model 在一次 load 后先 warm-up，再执行 measured repeats，避免把首次初始化混入正式统计。

Response 每个 case/model 返回：

- `measurements[]`：每次正式测量原始 metrics/error。
- `aggregate`：每个指标的 `count/mean/median/min/max/p95/variance`。
- `successful_runs` / `measured_runs`。
- 一份代表音频 `audio_url`（第一份成功正式测量）。
- `metadata`：runtime/model_version/quantization 等。
- status：`success | partial | error`。

## 6. Run Artifact

单轮：

```text
exports/<run_id>/
  audio/<model_id>.wav
  benchmark_report.json
  environment.json
```

Suite：

```text
exports/<run_id>/
  audio/<case_id>__<model_id>.wav
  benchmark_report.json
  environment.json
```

Blind Reveal 后可增加 `blind_scores.json`。

## 7. 下载与 Export

### `GET /api/v1/audio/download/{run_id}/{filename}`

只允许安全 `.wav` basename，禁止路径穿越。

### `GET /api/v1/export/{run_id}`

ZIP 包含：

- `audio/*.wav`
- `benchmark_report.json`
- `environment.json`
- optional `blind_scores.json`

## 8. Streaming

### `WS /api/v1/tts/stream?model=<model_id>`

仅 `capabilities.streaming=true` 的可用模型开放。首个可播放 `pcm_s16le` chunk 才计 TTFB；非流式 benchmark 不伪造 TTFB。

## 9. 错误码

| 应用码 | HTTP | 含义 |
|---:|---:|---|
| 1001 | 400 | 输入/路径无效 |
| 1002 | 404 | 模型、run、case 或音频不存在/不可用 |
| 1003 | 409 | 参数与 capability 冲突 |
| 2001 | 503 | CPU/系统资源暂不可用 |
| 2002 | 503 | 内存保护触发 |
| 3001 | 504 | 推理超时 |
| 3002 | 500 | 模型推理内部错误 |

## 10. Phase 2

长时间压测如需异步语义，再增加 `/jobs` 系列接口；不得改变现有同步 `/benchmark/run` 与 `/benchmark/suite` 的含义。
