## 2. 已冻结的关键实现决策

| 决策项 | 统一口径 |
|---|---|
| Python 包目录 | `src/edgetts_arena/` |
| 模型列表 API | `GET /api/v1/system/models` |
| Benchmark API | MVP 使用同步 `POST /api/v1/benchmark/run` |
| Benchmark 标识 | 使用 `run_id`，不使用具有异步含义的 `task_id` |
| 模型能力 | 每个 Adapter 必须声明 `capabilities` |
| 性能统计 | 由独立 `MetricsCollector` 负责，不由 Adapter 自行维护 `get_stats()` |
| 模型生命周期 | lazy load + 可选 keep-in-memory + 显式 unload |
| 默认调度 | `sequential`，并发模式用于压力/吞吐测试，不用于纯净单模型基准 |
| 依赖隔离 | MVP 优先单一兼容环境；冲突模型后续采用独立 subprocess/venv worker |
| CPU affinity | best-effort；线程数限制为跨平台基础能力 |
| TTFB | 真流式模型统计首个可播放音频 chunk；非流式模型返回 `null` |
| 性能目标 | 文档中的 RTF/RAM/TTFB 均为 benchmark target，不是运行时硬编码事实 |
| 不支持参数 | API 保留统一字段，但必须依据 capability 校验并给出 warning/error |

## 5. 实现原则

1. **先跑通骨架，再接重模型**：真实模型下载和 CPU 优化不得阻塞核心架构实现。
2. **Capability 驱动**：UI/API 不假设所有模型都支持 streaming、seed、speed、voice 或 voice clone。
3. **Benchmark 可复现**：报告必须包含 CPU、OS、Python、运行时版本、线程数、模型版本/量化方式等环境信息。
4. **观测与推理解耦**：Adapter 只负责模型能力，MetricsCollector 负责统一统计。
5. **性能数据以实测为准**：任何“预计 RTF/内存”不得直接写成产品承诺或 pass/fail 常量。
6. **失败隔离优先**：单模型异常不得导致 Web/API 主进程退出。
