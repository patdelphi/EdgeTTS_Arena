# 本地部署与验收指南

> 版本：v0.2（2026-09-03）  
> 目标：从全新 clone 到主 Arena API/UI、Dummy、Piper、Kokoro 与 Standard Suite 可执行验证；扩展模型可通过独立 Python/venv worker 接入。

## 1. 当前可测试范围

**主 Arena 已达到本地部署测试条件。** 推荐首次部署使用 Python 3.11。

主环境支持：Dummy、Piper、Kokoro int8、FastAPI、Gradio Arena UI、Blind AB、Standard Benchmark Suite、ZIP/report/environment 导出。

扩展模型：

- CosyVoice 300M SFT：Ubuntu x86_64 独立真实 CPU gate 已通过；专用 external Python worker 路由已接入；默认仍 `experimental + disabled`。
- MeloTTS：Ubuntu x86_64 独立真实 CPU gate 已通过；专用 external Python worker 路由已接入；默认仍 `experimental + disabled`。
- Qwen3-TTS 0.6B：仍是 unavailable placeholder。

不要把 CosyVoice/MeloTTS 的官方完整依赖直接装进主 Arena UI venv；使用各自 venv，并通过 `worker_python` 或环境变量告诉主 Arena 使用哪个 Python。

## 2. 创建主 Arena 环境

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

### macOS / Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

Python 3.10 或 3.12 也可；主 CI 三个版本均已通过。

## 3. 主环境 Doctor

```bash
edgetts-arena doctor --ui --exports-root exports/doctor
```

通过条件：Python/config、exports 可写、Dummy 真生成 WAV、FastAPI app 可创建、Gradio UI 可挂载。

Doctor 通过后再准备真实模型，以便把“项目环境问题”和“模型资产问题”分开定位。

## 4. 准备 Piper

```bash
python -m piper.download_voices en_US-lessac-low --data-dir models/piper
edgetts-arena piper \
  --model models/piper/en_US-lessac-low.onnx \
  --text "Edge TTS Arena local Piper test." \
  --threads 2 \
  --output exports/local-piper.wav
```

Windows PowerShell 可把续行命令改成一行。

## 5. 准备 Kokoro int8

### Windows PowerShell

```powershell
New-Item -ItemType Directory -Force models/kokoro | Out-Null
curl.exe -fL --retry 3 -o models/kokoro/kokoro-v1.0.int8.onnx https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
curl.exe -fL --retry 3 -o models/kokoro/voices-v1.0.bin https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
```

### macOS / Linux

```bash
mkdir -p models/kokoro
curl -fL --retry 3 -o models/kokoro/kokoro-v1.0.int8.onnx \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
```


## 6. 在 Arena 中启用 Piper/Kokoro

编辑 `config/models_config.yaml`：

```yaml
  - id: piper
    enabled: true
    adapter: piper
    model_path: ./models/piper

  - id: kokoro
    enabled: true
    adapter: kokoro
    model_path: ./models/kokoro
```

首次验收时 CosyVoice、MeloTTS、Qwen3 可继续保持 `enabled: false`。

## 7. 启动 UI/API

```bash
edgetts-arena serve --ui
```

- Arena：`http://127.0.0.1:8000/arena/`
- OpenAPI：`http://127.0.0.1:8000/docs`
- Health：`GET http://127.0.0.1:8000/healthz`
- Models：`GET http://127.0.0.1:8000/api/v1/system/models`

模型采用 lazy load，不要求服务启动时全部常驻内存。

## 8. 主 Arena 本地验收顺序

1. `edgetts-arena doctor --ui`
2. Dummy CLI 生成 WAV
3. Piper CLI 生成 WAV
4. Kokoro CLI 生成 WAV
5. `edgetts-arena serve --ui`
6. Arena 单模型各跑一次
7. Piper + Kokoro Sequential 对比
8. Blind AB 完成一轮评分与 Reveal
9. Standard Suite 先跑 TC-01/TC-02，warm-up 1 + measured 3
10. 下载 ZIP，确认 WAV、`benchmark_report.json`、`environment.json`

首次验收不要用 Concurrent 做质量/性能排名；Concurrent 是 pressure/throughput 模式。

## 9. CLI Standard Suite smoke

```bash
edgetts-arena suite \
  --models dummy \
  --cases TC-01 TC-02 \
  --warmup-runs 1 \
  --measured-runs 3 \
  --threads 2
```

报告应包含原始 measurement、mean/median/min/max/P95/variance、环境信息、requested/effective thread settings 和模型 metadata。

## 10. CosyVoice 独立 venv + worker

CosyVoice 的已验证基线为 Ubuntu 24.04 / Python 3.10 / CPU-only PyTorch + ONNX Runtime。

先建立独立 venv 并按 Extended Model Gate 的 pin 安装 CosyVoice 运行时。该 venv 还必须具备 external worker 基础依赖，例如 NumPy、SoundFile、psutil、PyYAML；项目 source 会由主 Arena 自动通过 `PYTHONPATH` 注入，不需要把 CosyVoice 的完整依赖装入主 UI venv。

模型本体准备后，先准备 WeText：

```bash
python scripts/prepare_cosyvoice_frontend.py --output models/cosyvoice/wetext
```

它只准备以下 5 个 FST，并写 `asset_manifest.json`：

```text
en/tn/tagger.fst
en/tn/verbalizer.fst
zh/tn/tagger.fst
zh/tn/verbalizer.fst
zh/tn/verbalizer_remove_erhua.fst
```

运行时设置：

```bash
export EDGETTS_ARENA_COSYVOICE_WETEXT_DIR="$PWD/models/cosyvoice/wetext"
export EDGETTS_ARENA_COSYVOICE_PYTHON="$PWD/.venv-cosyvoice/bin/python"
```

Windows PowerShell：

```powershell
$env:EDGETTS_ARENA_COSYVOICE_WETEXT_DIR = (Resolve-Path models/cosyvoice/wetext)
$env:EDGETTS_ARENA_COSYVOICE_PYTHON = (Resolve-Path .venv-cosyvoice\Scripts\python.exe)
```

## 11. MeloTTS 独立 venv + worker

按 Extended Model Gate 的 pinned source 建立 Python 3.10 venv，准备 ZH config/checkpoint 与 `model.json`，并设置：

```bash
export EDGETTS_ARENA_MELOTTS_PYTHON="$PWD/.venv-melotts/bin/python"
```

Windows PowerShell：

```powershell
$env:EDGETTS_ARENA_MELOTTS_PYTHON = (Resolve-Path .venv-melotts\Scripts\python.exe)
```

## 12. 检查专用 Workers

当两个环境变量已设置后：

```bash
edgetts-arena doctor --workers --exports-root exports/worker-doctor
```

该命令会分别启动配置中的专用 Python，用 external worker JSON 协议生成 Dummy WAV。通过说明：解释器可启动、项目 source 可导入、基础 worker 依赖与协议可运行。

它**不检查真实 CosyVoice/MeloTTS 模型推理**。真实模型仍应先按 Extended Model Gate/本地 smoke 验证。

`GET /api/v1/system/models` 可看到：

```json
{
  "worker_mode": "external",
  "worker_python_configured": true
}
```

API 不返回本机解释器绝对路径。

## 13. 启用扩展模型

完成模型资产、独立 venv、环境变量、`doctor --workers` 与真实模型 smoke 后，再显式把对应模型 `enabled` 改为 `true`。例如：

```yaml
  - id: cosyvoice-300m-sft
    enabled: true
    adapter: cosyvoice
    model_path: ./models/cosyvoice/CosyVoice-300M-SFT
    keep_in_memory: false
    worker_python_env: EDGETTS_ARENA_COSYVOICE_PYTHON
```

此时主 Arena 的 BenchmarkService、Standard Suite 和 UI 调用会把该模型推理路由到专用 Python worker，而不是主 UI venv。

## 15. 判定“本地部署测试通过”

主 Arena：

- `doctor --ui` 成功
- Dummy/Piper/Kokoro CLI 均生成非空 WAV
- `/healthz` 返回 200
- `/arena/` 正常打开
- Piper/Kokoro 可在 Arena 中完成 Sequential 推理
- Standard Suite 可生成 `run_id`、WAV、report、environment 与 ZIP
- 一个模型失败时不会导致服务进程退出

若同时测试扩展模型，再增加：对应 venv 和模型资产准备完成、`doctor --workers` 成功、真实 synthesis smoke 成功、`/system/models` 显示 `worker_mode=external`。
