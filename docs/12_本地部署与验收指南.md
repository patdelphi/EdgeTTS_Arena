# 本地部署与验收指南

> 版本：v0.1（2026-09-03）  
> 目标：从全新 clone 到主 Arena API/UI、Dummy、Piper、Kokoro 与 Standard Suite 可执行验证。

## 1. 当前可测试范围

**主 Arena 已达到本地部署测试条件。** 推荐首次部署使用 Python 3.11。

主环境支持：

- Dummy
- Piper
- Kokoro int8
- FastAPI API
- Gradio Arena UI
- Blind AB
- Standard Benchmark Suite
- ZIP/report/environment 导出

扩展模型：

- CosyVoice 300M SFT：Ubuntu x86_64 独立真实 CPU gate 已通过；当前仍 `experimental + disabled`。
- MeloTTS：Ubuntu x86_64 独立真实 CPU gate 已通过；当前仍 `experimental + disabled`。
- Qwen3-TTS 0.6B：仍是 unavailable placeholder。

**不要把 CosyVoice/MeloTTS 的官方完整依赖直接装进主 Arena UI venv。** 当前应使用独立 venv 验证扩展模型，直到模型专用 worker/venv 正式接入。

## 2. 创建主 Arena 环境

Clone 后进入仓库目录。

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

### macOS / Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

如果本机没有 Python 3.11，也可使用 3.10 或 3.12；主 CI 三个版本均已通过。

## 3. 先跑部署 Doctor

```bash
edgetts-arena doctor --ui --exports-root exports/doctor
```

通过条件：

- Python 版本满足 `>=3.10,<3.13`
- config 可加载
- `exports/doctor` 可写
- Dummy 可以真实生成 WAV
- FastAPI app 可创建
- Gradio UI 可构建并挂载

Doctor 通过后，再安装/启用真实模型；这样可以把“项目环境问题”和“模型资产问题”分开定位。

## 4. 准备 Piper

下载官方低质量测试 voice：

```bash
python -m piper.download_voices en_US-lessac-low --data-dir models/piper
```

独立 smoke：

```bash
edgetts-arena piper \
  --model models/piper/en_US-lessac-low.onnx \
  --text "Edge TTS Arena local Piper test." \
  --threads 2 \
  --output exports/local-piper.wav
```

Windows PowerShell 可将反斜杠续行改为一行执行。

确认：

```text
models/piper/en_US-lessac-low.onnx
models/piper/en_US-lessac-low.onnx.json
exports/local-piper.wav
```

## 5. 准备 Kokoro int8

### Windows PowerShell

```powershell
New-Item -ItemType Directory -Force models/kokoro | Out-Null
curl.exe -fL --retry 3 -o models/kokoro/kokoro-v1.0.int8.onnx https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
curl.exe -fL --retry 3 -o models/kokoro/voices-v1.0.bin https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
```

### macOS / Linux

```bash
mkdir -p models/kokoro
curl -fL --retry 3 -o models/kokoro/kokoro-v1.0.int8.onnx \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
curl -fL --retry 3 -o models/kokoro/voices-v1.0.bin \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
```

独立 smoke：

```bash
edgetts-arena kokoro \
  --model models/kokoro/kokoro-v1.0.int8.onnx \
  --voice af_heart \
  --text "Edge TTS Arena local Kokoro test." \
  --threads 2 \
  --output exports/local-kokoro.wav
```

确认 `exports/local-kokoro.wav` 非空且可播放。

## 6. 在 Arena 中启用 Piper/Kokoro

编辑 `config/models_config.yaml`：

```yaml
  - id: piper
    enabled: true
    adapter: piper
    model_path: ./models/piper

  - id: kokoro
    enabled: true
    adapter: kokoro
    model_path: ./models/kokoro
```

CosyVoice、MeloTTS、Qwen3 暂保持 `enabled: false`。

## 7. 启动 UI

```bash
edgetts-arena serve --ui
```

浏览器打开：

```text
http://127.0.0.1:8000/arena/
```

API 文档：

```text
http://127.0.0.1:8000/docs
```

健康检查：

```text
GET http://127.0.0.1:8000/healthz
```

模型状态：

```text
GET http://127.0.0.1:8000/api/v1/system/models
```

预期 Piper/Kokoro 在资产与配置正确时为可加载状态；模型仍采用 lazy load，不要求服务启动时全部常驻内存。

## 8. 本地验收顺序

建议按以下顺序执行，失败时容易定位：

1. `edgetts-arena doctor --ui`
2. Dummy CLI 生成 WAV
3. Piper CLI 生成 WAV
4. Kokoro CLI 生成 WAV
5. `edgetts-arena serve --ui`
6. Arena 单模型各跑一次
7. Piper + Kokoro 做 Sequential 对比
8. Blind AB 完成一轮评分与 Reveal
9. Standard Suite 先跑 TC-01/TC-02，warm-up 1 + measured 3
10. 下载 ZIP，确认 WAV、`benchmark_report.json`、`environment.json` 存在

不要在首次验收就使用 Concurrent 做质量/性能排名；Concurrent 是 pressure/throughput 模式。

## 9. CLI Standard Suite smoke

先用 Dummy 验证完整 benchmark/archive 链路：

```bash
edgetts-arena suite \
  --models dummy \
  --cases TC-01 TC-02 \
  --warmup-runs 1 \
  --measured-runs 3 \
  --threads 2
```

再将 `--models` 换成已经启用并准备好资产的真实模型。

验收 report 应同时包含：

- 原始 measurement
- mean / median / min / max / P95 / variance
- OS/CPU/RAM/Python/package versions
- requested/effective thread settings
- model runtime/version/quantization metadata

## 10. CosyVoice 独立验证

CosyVoice 当前只建议在独立 venv 中验证。已通过的 CI 基线为 Ubuntu 24.04 / Python 3.10 / CPU-only PyTorch + ONNX Runtime。

模型本体准备完成后，必须先准备本地 WeText 前端：

```bash
python scripts/prepare_cosyvoice_frontend.py --output models/cosyvoice/wetext
```

它只下载以下 5 个 FST，并写 `asset_manifest.json` SHA-256：

```text
en/tn/tagger.fst
en/tn/verbalizer.fst
zh/tn/tagger.fst
zh/tn/verbalizer.fst
zh/tn/verbalizer_remove_erhua.fst
```

运行时可显式设置：

```bash
export EDGETTS_ARENA_COSYVOICE_WETEXT_DIR="$PWD/models/cosyvoice/wetext"
```

Windows PowerShell 等价为：

```powershell
$env:EDGETTS_ARENA_COSYVOICE_WETEXT_DIR = (Resolve-Path models/cosyvoice/wetext)
```

项目 CI 已验证：将 WeText 的 `snapshot_download()` 改成调用即失败后，Adapter 仍能从本地 FST 完成 `load_model()`，因此模型运行阶段不依赖该隐式下载路径。

CosyVoice gate 的单次记录为 4.098s 音频、17.875s inference、RTF 4.362、peak RSS 4181 MB。该数据只说明真实 CPU 路线可执行，不是你的本机性能预期。

## 12. 判定“本地部署测试通过”

满足以下条件即可认为当前机器的主 Arena 部署通过：

- `doctor --ui` 成功
- Dummy/Piper/Kokoro 三条 CLI smoke 均生成非空 WAV
- `/healthz` 返回 200
- `/arena/` 正常打开
- Piper/Kokoro 可在 Arena 中完成 Sequential 推理
- Standard Suite 可生成 `run_id`、WAV、report、environment 与 ZIP
- 一个模型失败时不会导致服务进程退出

完成这些项目后，再开始针对你实际机器做线程数、内存阈值、模型常驻策略和 RTF 的性能调优。
