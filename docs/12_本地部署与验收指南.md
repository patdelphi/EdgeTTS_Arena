# 本地部署与验收指南

> 版本：v1.0（2026-09-03） ｜ **主 Arena ready，可开始本地部署测试**；扩展 bootstrap、Qwen quant A/B、真实设备 acceptance 与 Concurrent calibration 工具链 ready

## 1. 主 Arena

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
pytest
edgetts-arena doctor --ui --exports-root exports/doctor
edgetts-arena serve --ui
```

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
pytest
edgetts-arena doctor --ui --exports-root exports/doctor
edgetts-arena serve --ui
```

验收顺序：Doctor → Dummy/API → Piper → Kokoro → UI → Sequential → Blind AB → Standard Suite → ZIP/report/environment。

## 2. Python 扩展模型 bootstrap

统一入口：

```bash
python scripts/bootstrap_extended_model.py MODEL --python PYTHON
```

默认只输出 plan；`--execute` 才创建 venv、联网安装/下载。Qwen3 official 推荐 Python 3.11；MeloTTS/CosyVoice 使用 Python 3.10。CosyVoice 主机需要先安装 git + sox/libsox，脚本不会自动 sudo/brew。

执行成功后输出：

```text
exports/bootstrap/<model>/bootstrap_plan.json
exports/bootstrap/<model>/env.sh
exports/bootstrap/<model>/env.ps1
```

bootstrap 会固定 heavy gate 已验证的 source/runtime/model revision、做 import/runtime preflight，并执行 `doctor --worker MODEL_ID`。`--skip-assets` 可只装 runtime，`--no-doctor` 可跳过最终 Doctor。

## 3. Qwen3 native INT8/INT4 bootstrap

推荐 CPU 路线使用独立 planner：

```bash
python scripts/bootstrap_qwen3_native.py --python python3.11
python scripts/bootstrap_qwen3_native.py --python python3.11 --execute
```

执行链：pinned runtime clone/checkout → `make blas` → `qwen_tts --caps` → `--self-test` → pinned official 0.6B model → paired INT8/INT4 manifests → Arena Adapter preflight。

Linux：先提供 git/make/gcc 与 OpenBLAS development library；macOS 使用 Accelerate；Windows 原生不是当前验证基线，建议 WSL/Linux。

## 4. Qwen Blind AB

启用两个实验项后：

```text
qwen3-tts-0.6b-native-int8
qwen3-tts-0.6b-native-int4
```

选择共同 Voice/Language，固定同一 seed，Sequential 生成后进入 Blind AB。全部匿名评分完成后再 Reveal；保存 `blind_scores.json` + benchmark report + audio。工具 ready 不等于 INT4 质量已通过。

## 5. 单模型真实目标设备验收

```bash
unset OPENBLAS_NUM_THREADS
python scripts/target_device_acceptance.py qwen3-native \
  --model-path models/qwen3-native/int8/model.json \
  --text "你好，这是一条 EdgeTTS Arena 真实设备验收语音。" \
  --voice Vivian --language zh --seed 42 \
  --threads 2 --runs 3 \
  --require-arch aarch64,arm64 \
  --max-rtf 2.0 --max-peak-rss-mb 3500 \
  --output-dir exports/target-device/qwen3-int8
```

输出 environment、每次 WAV/JSON、aggregate、acceptance report 与 ZIP。阈值按**最差一次**判断。

## 6. Concurrent 真机校准

对同一组已启用模型，每轮按 Sequential baseline → Concurrent pressure 成对执行：

```bash
python scripts/target_device_concurrent_calibration.py \
  --models piper kokoro \
  --text "Concurrent target-device calibration." \
  --threads 2 --runs 3 \
  --max-rtf-slowdown-ratio 1.8 \
  --max-concurrent-rtf 2.0 \
  --max-concurrent-peak-rss-mb 3500 \
  --output-dir exports/target-concurrent/piper-kokoro
```

报告按模型聚合：

- Sequential / Concurrent RTF；
- `rtf_slowdown_ratio = concurrent_rtf / sequential_rtf`；
- Sequential / Concurrent peak RSS 与 delta；
- Sequential / Concurrent CPU；
- requested/effective threads、total thread budget、ResourceGuard warnings；
- 每一对 sequential/concurrent 原始 run ID 和结果。

阈值仍由目标设备和 SLA 给出。没有真实设备报告前，只能标记“calibration tooling ready”，不能标记“Concurrent 真机预算已验证”。

## 7. 证据目录隔离

`target_device_acceptance.py` 与 `target_device_concurrent_calibration.py` 默认要求新的空 output-dir；若目录已有内容或同名 ZIP 已存在，会拒绝执行。这样旧证据不会混进新 ZIP。

确认要覆盖时显式：

```bash
... --output-dir exports/target-device/run-a --overwrite
```

`--overwrite` 会先删除旧目录和旧 ZIP，再执行新一轮测试。

## 8. OOM 诊断

Worker report 的 `oom_classification`：

- `none`
- `worker_memory_error`
- `cgroup_oom_kill_observed`
- `sigkill_suspected`

显式 MemoryError 是直接证据；Linux cgroup v2 `oom_kill` 增量是更强但 cgroup-wide 的 observed evidence；裸 SIGKILL 只标 suspected；Arena watchdog timeout 自身 kill 不标 OOM。

## 9. Gate 边界

必须分开记录：

1. bootstrap/runtime ready；
2. real-model synthesis ready；
3. hosted performance baseline；
4. human quality gate；
5. target-device performance gate；
6. Concurrent target-device calibration。

任何一项不能代替另一项。
