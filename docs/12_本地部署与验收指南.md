# 本地部署与验收指南

> 版本：v0.9（2026-09-03） ｜ **主 Arena ready，可开始本地部署测试**；扩展模型 pinned bootstrap、Qwen quant A/B harness 与目标设备验收包 ready

## 1. 主 Arena：现在可以开始本地部署测试

主 Arena 本地部署测试不依赖扩展模型，也不依赖真实 ARM/弱设备结果。推荐 Python 3.11：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
pytest
edgetts-arena doctor --ui --exports-root exports/doctor
edgetts-arena serve --ui
```

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
pytest
edgetts-arena doctor --ui --exports-root exports/doctor
edgetts-arena serve --ui
```

验收顺序：Doctor → Dummy/API → Piper → Kokoro → UI → Sequential 对比 → Blind AB → Standard Suite TC-01/02 → ZIP/report/environment。

本地启动后：

```text
API    http://127.0.0.1:8000
Arena  http://127.0.0.1:8000/arena/
Docs   http://127.0.0.1:8000/docs
```

## 2. 扩展模型 pinned bootstrap

扩展模型仍与主 UI venv 隔离。统一入口：

```bash
python scripts/bootstrap_extended_model.py MODEL --python PYTHON
```

不加 `--execute` 时只打印完整计划，不创建 venv、不安装依赖、不下载模型。建议先检查计划，再执行：

```bash
# Qwen3 official：Python 3.11
python scripts/bootstrap_extended_model.py qwen3 --python python3.11 --execute

# MeloTTS：Python 3.10
python scripts/bootstrap_extended_model.py melotts --python python3.10 --execute

# CosyVoice：Python 3.10；主机需预先安装 git + sox/libsox
python scripts/bootstrap_extended_model.py cosyvoice --python python3.10 --execute
```

Windows 可把 `--python` 指向具体解释器，例如 `py -3.10` 不能作为单个 executable 参数，因此建议传 Python 可执行文件绝对路径，或先用对应 Python 运行脚本。bootstrap 会在创建 venv 前再次检查 Python major/minor。

每个 profile 都会：

1. 创建 `.venv-qwen3` / `.venv-melotts` / `.venv-cosyvoice`（可用 `--venv` 覆盖）。
2. 安装与 hosted heavy gate 对齐的 pinned CPU runtime/source。
3. 做 runtime import/preflight。
4. 默认准备 pinned 本地模型资产；`--skip-assets` 可关闭。
5. 最后执行定向 `doctor --worker MODEL_ID`；`--no-doctor` 可关闭。
6. 成功后写出：

```text
exports/bootstrap/<model>/bootstrap_plan.json
exports/bootstrap/<model>/env.sh
exports/bootstrap/<model>/env.ps1
```

启动主 Arena 前加载对应环境文件：

```bash
source exports/bootstrap/qwen3/env.sh
```

PowerShell：

```powershell
. .\exports\bootstrap\qwen3\env.ps1
```

CosyVoice 环境文件除 `EDGETTS_ARENA_COSYVOICE_PYTHON` 外还包含本地 WeText 路径与 vendor `PYTHONPATH`；不要把这些依赖强装进主 UI venv。

### bootstrap 与 gate 的边界

- bootstrap success：专用环境、资产准备流程、runtime preflight、Worker Doctor 成功。
- real-model smoke success：该模型在本机真正生成 WAV。
- target-device pass：在指定真实目标设备上满足显式性能阈值。

三者不能互相替代。建议 bootstrap 完成后仍运行对应 `scripts/real_model_smoke.py`。

## 3. Qwen native pair

编译 pinned native runtime、准备官方 0.6B CustomVoice snapshot 后：

```bash
python scripts/prepare_qwen3_native_variants.py \
  --binary runtime/qwen3-tts-c/qwen_tts \
  --model-dir models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice \
  --output-root models/qwen3-native \
  --default-voice Vivian \
  --default-language Chinese
```

检查：

```text
models/qwen3-native/int8/model.json
models/qwen3-native/int4/model.json
```

不要预设 `OPENBLAS_NUM_THREADS`。

## 4. Qwen 实验启用

把配置中的以下两项都改为 `enabled: true`：

```text
qwen3-tts-0.6b-native-int8   # default num_threads=2
qwen3-tts-0.6b-native-int4   # default num_threads=4
```

两者继续保持 `experimental: true`。

## 5. Blind AB 验收

启动 UI 后：

1. 同时选择 INT8 与 INT4。
2. Shared Voice 选 Vivian；Shared Language 选 zh；Seed 设相同值。
3. Sequential Run benchmark。
4. Start Blind AB。
5. 不 Reveal，先完成 Sample A/B 的 Naturalness / Intelligibility / Prosody。
6. 完成全部评分后 Reveal。
7. 下载 ZIP，保留 `blind_scores.json` + `benchmark_report.json` + audio。

建议分别对中文、英文、日文等目标语言单独运行；每轮保证共同 text/voice/language/seed。

当前只可标记“A/B 验收环境已就绪”，不能标记“INT4 质量通过”。

## 6. 真实目标设备验收

目标设备上使用统一验收包，而不是人工抄指标：

```bash
unset OPENBLAS_NUM_THREADS
python scripts/target_device_acceptance.py qwen3-native \
  --model-path models/qwen3-native/int8/model.json \
  --text "你好，这是一条 EdgeTTS Arena 真实设备验收语音。" \
  --voice Vivian --language zh --seed 42 \
  --threads 2 --runs 3 \
  --require-arch aarch64,arm64 \
  --max-rtf 2.0 \
  --max-peak-rss-mb 3500 \
  --output-dir exports/target-device/qwen3-int8
```

输出包含：

```text
exports/target-device/qwen3-int8/
  environment.json
  run-01.wav / run-01.json
  run-02.wav / run-02.json
  run-03.wav / run-03.json
  acceptance_report.json
exports/target-device/qwen3-int8.zip
```

判定原则：

- `all_runs_successful` 必须通过。
- `--require-arch` 可限定实际架构。
- native 路线会检查 `OPENBLAS_NUM_THREADS` 未预设。
- `--max-rtf` 与 `--max-peak-rss-mb` 都按**最差一次**结果判断，不取最好成绩。
- 性能阈值由目标设备和业务 SLA 明确给出；不提供阈值时只能证明“真实 synthesis 成功”，不能宣称性能达标。
