# 本地部署与验收指南

> 版本：v0.3（2026-09-03）  
> 目标：从全新 clone 到主 Arena API/UI、Dummy、Piper、Kokoro 与 Standard Suite 可执行验证；扩展模型通过独立 Python/venv worker 接入。

## 1. 当前可测试范围

**主 Arena 已达到本地部署测试条件。** 推荐首次部署使用 Python 3.11。

主环境支持：Dummy、Piper、Kokoro int8、FastAPI、Gradio Arena UI、Blind AB、Standard Benchmark Suite、ZIP/report/environment 导出。

扩展模型：

- CosyVoice 300M SFT：Ubuntu x86_64 独立真实 CPU gate 已通过；external worker 已接入；默认 `experimental + disabled`。
- MeloTTS：Ubuntu x86_64 独立真实 CPU gate 已通过；external worker 已接入；默认 `experimental + disabled`。
- Qwen3-TTS 0.6B CustomVoice：官方 `qwen-tts` CPU Adapter、worker、模型准备脚本与 manual heavy gate 已接入；真实 heavy CPU synthesis gate 尚待实际通过；默认 `experimental + disabled`。

不要把扩展模型完整官方依赖直接装进主 Arena UI venv；使用各自 venv。

## 2. 创建主 Arena 环境

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

### macOS / Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
```

## 3. 主环境 Doctor

```bash
edgetts-arena doctor --ui --exports-root exports/doctor
```

通过条件：Python/config、exports 可写、Dummy 真生成 WAV、FastAPI app 可创建、Gradio UI 可挂载。

## 4. 准备 Piper

```bash
python -m piper.download_voices en_US-lessac-low --data-dir models/piper
edgetts-arena piper \
  --model models/piper/en_US-lessac-low.onnx \
  --text "Edge TTS Arena local Piper test." \
  --threads 2 \
  --output exports/local-piper.wav
```

## 5. 准备 Kokoro int8

```bash
mkdir -p models/kokoro
curl -fL --retry 3 -o models/kokoro/kokoro-v1.0.int8.onnx \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.int8.onnx
curl -fL --retry 3 -o models/kokoro/voices-v1.0.bin \
  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin

edgetts-arena kokoro \
  --model models/kokoro/kokoro-v1.0.int8.onnx \
  --voice af_heart \
  --text "Edge TTS Arena local Kokoro test." \
  --threads 2 \
  --output exports/local-kokoro.wav
```

Windows 可用 `curl.exe` 并改成单行命令。

## 6. 在 Arena 中启用 Piper/Kokoro

编辑 `config/models_config.yaml` 将对应 `enabled` 改为 `true`，并确认 `model_path` 与本地文件匹配。首次主 Arena 验收时所有扩展模型可继续保持 `enabled: false`。

## 7. 启动 UI/API

```bash
edgetts-arena serve --ui
```

- Arena：`http://127.0.0.1:8000/arena/`
- OpenAPI：`http://127.0.0.1:8000/docs`
- Health：`GET http://127.0.0.1:8000/healthz`
- Models：`GET http://127.0.0.1:8000/api/v1/system/models`

## 8. 主 Arena 本地验收顺序

1. `edgetts-arena doctor --ui`
2. Dummy CLI 生成 WAV
3. Piper CLI 生成 WAV
4. Kokoro CLI 生成 WAV
5. `edgetts-arena serve --ui`
6. Arena 单模型各跑一次
7. Piper + Kokoro Sequential 对比
8. Blind AB 一轮评分与 Reveal
9. Standard Suite TC-01/TC-02，warm-up 1 + measured 3
10. 下载 ZIP，确认 WAV、`benchmark_report.json`、`environment.json`

首次验收不要用 Concurrent 做质量/性能排名；Concurrent 是 pressure/throughput 模式。

## 9. CLI Standard Suite smoke

```bash
edgetts-arena suite \
  --models dummy \
  --cases TC-01 TC-02 \
  --warmup-runs 1 \
  --measured-runs 3 \
  --threads 2
```

## 10. CosyVoice 独立 venv + worker

CosyVoice 已验证基线为 Ubuntu 24.04 / Python 3.10 / CPU-only PyTorch + ONNX Runtime。按 Extended Model Gate 的 pin 安装运行时，并确保 NumPy、SoundFile、psutil、PyYAML 等 external worker 基础依赖存在。

准备 WeText：

```bash
python scripts/prepare_cosyvoice_frontend.py --output models/cosyvoice/wetext
export EDGETTS_ARENA_COSYVOICE_WETEXT_DIR="$PWD/models/cosyvoice/wetext"
export EDGETTS_ARENA_COSYVOICE_PYTHON="$PWD/.venv-cosyvoice/bin/python"
```

## 11. MeloTTS 独立 venv + worker

按 Extended Model Gate 的 pinned source 建立 Python 3.10 venv，准备 ZH config/checkpoint 与 `model.json`：

```bash
export EDGETTS_ARENA_MELOTTS_PYTHON="$PWD/.venv-melotts/bin/python"
```

## 12. Qwen3-TTS 0.6B 独立 venv + worker

建议使用单独 Python 3.11 环境；CPU 路线不需要安装 FlashAttention。以下命令以 Linux/macOS 为例：

```bash
python3.11 -m venv .venv-qwen3
source .venv-qwen3/bin/activate
python -m pip install --upgrade pip
python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.8.0 torchaudio==2.8.0
python -m pip install qwen-tts==0.1.1
python -m pip install -e .

python scripts/prepare_qwen3_model.py \
  --output models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice

python scripts/real_model_smoke.py qwen3 \
  --model-path models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice \
  --voice Vivian \
  --text "你好，这是一条 EdgeTTS Arena 的 Qwen3 CPU 验证语音。" \
  --threads 2 \
  --output exports/qwen3-local.wav \
  --report exports/qwen3-local.json

export EDGETTS_ARENA_QWEN3_PYTHON="$PWD/.venv-qwen3/bin/python"
```

Windows PowerShell 的解释器变量：

```powershell
$env:EDGETTS_ARENA_QWEN3_PYTHON = (Resolve-Path .venv-qwen3\Scripts\python.exe)
```

注意：当前官方 CPU fp32 路线是功能基线，不代表已完成低内存/最佳 RTF 优化。真实 smoke 成功前不要把 Qwen3 写成 verified。

## 13. 检查专用 Workers

默认配置声明了三个扩展模型 worker 环境变量。要一次执行完整 worker Doctor，请先设置：

```text
EDGETTS_ARENA_QWEN3_PYTHON
EDGETTS_ARENA_COSYVOICE_PYTHON
EDGETTS_ARENA_MELOTTS_PYTHON
```

然后：

```bash
edgetts-arena doctor --workers --exports-root exports/worker-doctor
```

该命令分别启动专用 Python，用 external worker JSON 协议生成 Dummy WAV。通过只说明解释器、项目 source、基础 worker 依赖与协议可运行，**不检查真实模型推理**。

## 14. 启用扩展模型

完成对应模型资产、独立 venv、环境变量、worker Doctor 与真实模型 smoke 后，再显式把对应模型 `enabled` 改为 `true`。Qwen3 示例：

```yaml
  - id: qwen3-tts-0.6b
    enabled: true
    adapter: qwen3
    model_path: ./models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice
    keep_in_memory: false
    worker_python_env: EDGETTS_ARENA_QWEN3_PYTHON
```

BenchmarkService、Standard Suite 和 UI 会把模型推理路由到专用 Python worker。
