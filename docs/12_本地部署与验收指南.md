# 本地部署与验收指南

> 版本：v0.4（2026-09-03）  
> 目标：主 Arena 本地验收 + 扩展模型独立 worker 验收。

## 1. 当前范围

**主 Arena 已达到本地部署测试条件。** 主环境：Dummy、Piper、Kokoro int8、FastAPI、Gradio Arena、Blind AB、Standard Suite、ZIP/report/environment。

扩展模型默认 `experimental + disabled`：CosyVoice/MeloTTS real CPU gate 已通过；Qwen3 0.6B CustomVoice 官方 CPU Adapter/worker/资产准备/manual gate 已完成，real heavy CPU synthesis 尚待实际通过。

## 2. 主 Arena

推荐 Python 3.11：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev,ui,piper,kokoro]"
edgetts-arena doctor --ui --exports-root exports/doctor
edgetts-arena serve --ui
```

Windows PowerShell 使用 `py -3.11 -m venv .venv` 与 `.\.venv\Scripts\Activate.ps1`。

主验收顺序：Doctor → Dummy → Piper → Kokoro → UI/API → Sequential 对比 → Blind AB → Standard Suite TC-01/02 → ZIP/report/environment。

## 3. Piper / Kokoro

Piper：

```bash
python -m piper.download_voices en_US-lessac-low --data-dir models/piper
edgetts-arena piper --model models/piper/en_US-lessac-low.onnx --text "Piper test" --threads 2 --output exports/piper.wav
```

Kokoro：按 README/CI gate 下载 `kokoro-v1.0.int8.onnx` 与 `voices-v1.0.bin` 到 `models/kokoro/`，然后：

```bash
edgetts-arena kokoro --model models/kokoro/kokoro-v1.0.int8.onnx --voice af_heart --text "Kokoro test" --threads 2 --output exports/kokoro.wav
```

## 4. 扩展模型 worker 原则

不要把扩展模型完整官方依赖直接装进主 UI venv。分别建立 `.venv-qwen3`、`.venv-cosyvoice`、`.venv-melotts`，通过 `worker_python_env` 路由。

完整检查所有默认扩展模型时设置：

```text
EDGETTS_ARENA_QWEN3_PYTHON
EDGETTS_ARENA_COSYVOICE_PYTHON
EDGETTS_ARENA_MELOTTS_PYTHON
```

然后运行：

```bash
edgetts-arena doctor --workers --exports-root exports/worker-doctor
```

如果当前只准备了一个模型，可定向检查，不要求其余环境变量：

```bash
edgetts-arena doctor --worker qwen3-tts-0.6b --exports-root exports/qwen3-worker-doctor
edgetts-arena doctor --worker cosyvoice-300m-sft
edgetts-arena doctor --worker melotts-zh
```

`--worker MODEL_ID` 可重复，并隐含 `--workers`。未知 model id 或没有 dedicated worker 声明的模型会使 Doctor 失败并给出明确 check。

Doctor 的 worker probe 只生成 Dummy WAV，验证解释器、项目 source、基础依赖与 external worker 协议；**不检查真实模型推理**。

## 5. CosyVoice

按 Extended Model Gate pin 建立 Python 3.10 环境，准备模型与 WeText：

```bash
python scripts/prepare_cosyvoice_frontend.py --output models/cosyvoice/wetext
export EDGETTS_ARENA_COSYVOICE_WETEXT_DIR="$PWD/models/cosyvoice/wetext"
export EDGETTS_ARENA_COSYVOICE_PYTHON="$PWD/.venv-cosyvoice/bin/python"
edgetts-arena doctor --worker cosyvoice-300m-sft
```

## 6. MeloTTS

按 Extended Model Gate pinned source 建立 Python 3.10 环境，准备 ZH config/checkpoint 与 `model.json`：

```bash
export EDGETTS_ARENA_MELOTTS_PYTHON="$PWD/.venv-melotts/bin/python"
edgetts-arena doctor --worker melotts-zh
```

## 7. Qwen3-TTS 0.6B CustomVoice

建议独立 Python 3.11 CPU 环境；CPU 路线不要求 FlashAttention：

```bash
python3.11 -m venv .venv-qwen3
source .venv-qwen3/bin/activate
python -m pip install --upgrade pip
python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.8.0 torchaudio==2.8.0
python -m pip install qwen-tts==0.1.1
python -m pip install -e .
python scripts/prepare_qwen3_model.py --output models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice
export EDGETTS_ARENA_QWEN3_PYTHON="$PWD/.venv-qwen3/bin/python"
edgetts-arena doctor --worker qwen3-tts-0.6b
```

真实模型 smoke：

```bash
python scripts/real_model_smoke.py qwen3 \
  --model-path models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice \
  --voice Vivian \
  --text "你好，这是一条 EdgeTTS Arena 的 Qwen3 CPU 验证语音。" \
  --threads 2 \
  --output exports/qwen3-local.wav \
  --report exports/qwen3-local.json
```

Windows worker 变量：

```powershell
$env:EDGETTS_ARENA_QWEN3_PYTHON = (Resolve-Path .venv-qwen3\Scripts\python.exe)
```

当前 CPU fp32 是功能基线，不代表低内存/最佳 RTF 路线已经完成。真实 smoke/heavy gate 成功前保持 experimental。

## 8. 启用扩展模型

只有在对应 venv、模型资产、worker Doctor、真实 synthesis smoke 均通过后，才把该模型 `enabled` 改为 `true`。Qwen3：

```yaml
- id: qwen3-tts-0.6b
  enabled: true
  adapter: qwen3
  model_path: ./models/qwen3/Qwen3-TTS-12Hz-0.6B-CustomVoice
  keep_in_memory: false
  worker_python_env: EDGETTS_ARENA_QWEN3_PYTHON
```
