# 评测基准与测试用例集（Benchmark Suite）

> 版本：v0.3 ｜ Stage 5 已实现 ｜ 性能数据必须可复现

## 1. 指标

| 指标 | 定义 |
|---|---|
| Inference Time | 推理 wall-clock，不含 UI |
| Audio Duration | 输出样本数 / 实际 sample rate |
| RTF | inference / audio duration |
| TTFB | 首个可播放 chunk；非流式为 null |
| Peak RSS | 推理期间最大 RSS |
| RSS Delta | peak RSS - baseline RSS |
| Avg CPU | 采样期进程 CPU 使用率 |

## 2. 基准模式

### Sequential

标准横向基准和 Stage 5 repeated suite 固定使用 Sequential，避免模型间资源竞争污染 RTF/RSS/CPU。

### Concurrent

Stage 3 单轮 API 支持受控 Concurrent，但只用于压力/吞吐场景。Stage 6 再做完整并发 hardening 和独立报告解释。

## 3. 标准题库

`config/benchmark_presets.json` 是唯一运行时来源，版本当前为 `1.0`。

- **TC-01 日常短交互**：短句延迟、自然停顿。
- **TC-02 数字、单位与符号**：日期、负数、温度、时长、功率、价格。
- **TC-03 中英混读**：ONNX Runtime / CPU / latency / memory 等技术词。
- **TC-04 多音字**：重 / 行 / 还等上下文读音。
- **TC-05 长文本稳定性**：固定 300+ 中文字符，观察重复、漏字、异常停顿、语速/音量漂移、句尾截断。

TC-05 不再使用占位语料。

## 4. Warm-up 与 Repeats

默认：

```json
{"warmup_runs":1,"measured_runs":3}
```

规则：

1. 同一 case/model 只 load 一次。
2. warm-up 只用于初始化，不进入正式统计。
3. measured repeats 每次保存原始 metrics。
4. 第一份成功正式测量保存代表 WAV；避免把 3~20 份近似音频全部打包导致归档膨胀。
5. 某一次 measured 失败时保留该 repeat 的 error；其余 repeat 继续，最终 status 可为 partial。

## 5. 聚合统计

对每个指标分别计算：

- count
- mean
- median
- min
- max
- P95
- population variance

`ttfb_ms` 对非流式模型没有有效样本，因此 count=0，其余统计为 null。

## 6. 环境快照

每个 run 保存：

- OS / release / arch
- CPU brand
- physical/logical cores
- total/available RAM
- Python version / implementation / executable
- 关键 package versions
- cpu_threads_per_model
- OMP / MKL / OpenBLAS / NumExpr thread env

每个 successful model result 同时保留 Adapter metadata，包括 runtime、runtime_version、model_version、quantization、voice/language 等可用字段。

## 7. Report Schema

Repeated suite：

```text
schema_version = benchmark-suite-report-v1
request
  case_ids
  models
  cpu_threads_per_model
  warmup_runs
  measured_runs
  config
data
  run_id / timestamps
  suite_version
  cases[]
  models[]
  results[]
    case_id / model_id / status
    measurements[]
    aggregate
    metadata
    warnings / error
```

原始 measurement 必须保留，aggregate 不能成为唯一证据。

## 8. 工程通过条件

- 音频非空，无 NaN/Inf。
- sample rate > 0。
- RTF 有效时为有限正数。
- metrics 字段完整。
- 单模型/单 repeat 失败可解释且不拖垮整个 suite。
- report + environment + WAV 可从同一 run_id 导出。

## 9. 主观评测

Blind AB 仍保存原始 Naturalness / Intelligibility / Prosody 1~5，不强制合成一个“总分”。
