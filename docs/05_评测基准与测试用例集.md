# 评测基准与测试用例集（Benchmark Suite）

> 版本：v0.2 ｜ 原则：性能数据可复现、Sequential 与 Concurrent 分开解释

## 1. 指标定义

| 指标 | 定义 | 备注 |
|---|---|---|
| Inference Time | 模型推理 wall-clock 时间 | 不含 UI 渲染 |
| Audio Duration | 输出音频时长 | 基于实际 sample rate |
| RTF | `inference_time / audio_duration` | `<1` 表示生成速度快于音频播放时长 |
| TTFB | 请求开始到首个可播放音频 chunk | 仅真流式模型；否则 `null` |
| Peak RSS | worker 推理期间最大 RSS | MB |
| RSS Delta | `peak_rss - baseline_rss` | MB |
| Avg CPU | worker 采样期平均 CPU usage | 需记录采样方法 |

## 2. Benchmark 模式

### 2.1 Sequential

用于模型横向基准。模型逐个执行，默认线程数一致，尽量减少竞争。

### 2.2 Concurrent

用于压力和吞吐测试。结果反映资源竞争场景，不与 Sequential 的 RTF 排名直接混用。

## 3. 环境快照

每次 run 必须记录：

```json
{
  "os": "...",
  "arch": "...",
  "cpu_brand": "...",
  "physical_cores": 0,
  "logical_cores": 0,
  "total_ram_gb": 0,
  "python_version": "...",
  "package_versions": {},
  "thread_settings": {
    "cpu_threads_per_model": 4,
    "omp_num_threads": 4,
    "mkl_num_threads": 4
  }

```

每个模型还必须记录 `model_version/runtime/quantization`。

## 4. 标准化测试语料

### TC-01 日常短交互

“收到，已经在为您规划最优路线，请稍候。”

考核：短句延迟、自然停顿。

### TC-02 数字、单位与符号

“2026年9月3日，该设备在-15℃的环境下持续运行了8.5小时，功率约为120W，售价￥3,999元。”

考核：数字归一化、负数、温度、时长、单位、价格。

### TC-03 中英混读

“我们正在使用 ONNX Runtime 在 CPU 上部署 Kokoro 和 Qwen3-TTS 模型，并比较 latency、memory 和 audio quality。”

考核：code-switching、英文技术词、断句。

### TC-04 多音字

“重阳节那天，银行行长再次强调还款期限，各行各业都应遵守信用。”

考核：“重 / 行 / 还”等语境读音。

### TC-05 长文本稳定性

使用 300~500 中文字符的固定语料。

考核：重复、漏字、语速漂移、韵律衰减、异常终止。

## 5. 主观评测

Blind 模式建议三项 1~5 分：

- Naturalness
- Intelligibility
- Prosody

MVP 不强制合成一个“总分”用于宣称模型优劣；先保存原始评分和胜率。若后续建立综合分，应单独记录算法版本与权重。

## 6. 性能目标与通过条件

性能阈值分两类：

### A. 工程通过条件

- 输出音频非空、无 NaN/Inf。
- sample rate > 0。
- RTF 可计算时为有限正数。
- 指标字段完整。
- 失败结果可解释且不拖垮其他模型。

### B. 参考性能目标

RTF、TTFB、内存阈值只作为目标配置，不写死在 Adapter 或单元测试。不同 CPU 上单独维护 benchmark baseline。

示例：

```yaml
benchmark_targets:
  reference_machine: "local-dev"
  piper:
    rtf_max: 0.3
  kokoro-82m:
    rtf_max: 1.0
```

## 7. 重复性

- 同一 case 每模型建议 warm-up 1 次后测量 3 次。
- 报告保存 mean / median / min / max（Stage 5 实现）。
- `seed` 只对 capability 支持的模型启用。
