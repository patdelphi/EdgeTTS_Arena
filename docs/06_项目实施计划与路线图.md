## Stage 6 Watchdog 与 Worker 当前口径

- `BenchmarkService` / `RepeatedBenchmarkService` 默认启用进程隔离；仅嵌入式调用或测试可显式 `isolate_model_processes=False`。
- `keep_in_memory=false` 且未配置外部 Python：使用当前解释器的 `spawn` worker，支持 terminate/kill hard timeout。
- `keep_in_memory=false` 且配置 `worker_python`/`worker_python_env`：通过 JSON stdin/stdout 协议启动指定 Python 解释器；模型运行时依赖与主 Arena venv 分离。
- 默认扩展模型环境变量：`EDGETTS_ARENA_COSYVOICE_PYTHON`、`EDGETTS_ARENA_MELOTTS_PYTHON`。
- `edgetts-arena doctor --workers` 会对声明的专用 worker 解释器做协议 + Dummy WAV probe；它验证 worker 基础可运行性，不代替真实模型 synthesis gate。
- `/api/v1/system/models` 暴露 `worker_mode=in_process|spawn|external` 与 `worker_python_configured`，不回传本机 Python 绝对路径。
- Standard Suite 一个 `case/model` 作为一个 worker group，在 worker 内完成 warm-up + repeats。
- timeout → `3001`；worker crash → `3002`；故障后 Registry 状态恢复为 `unloaded`。
- isolated result 记录 PID / exit code / signal / elapsed / termination；显式 MemoryError → `2002`。
- SIGKILL 只记 `oom_suspected=true`（可能 OOM 或外部 kill），跨平台不伪造内核级确定归因。
- `keep_in_memory=true`：暂保留进程内常驻，明确 warning，不宣称 hard timeout。
- GitHub-hosted 原生 ARM64 与 1-CPU runner 已通过；ResourceGuard 使用 process/affinity/cgroup/host 中最保守 CPU 预算，并使用 host available/cgroup remaining 中更小的内存预算。
- MeloTTS real CPU gate：Ubuntu 24.04 / Python 3.10 / 2 threads，pinned source + Chinese model，真实 synthesis、WAV/JSON artifact 与 audio sanity gate 全通过。
- CosyVoice 300M SFT real CPU gate：Ubuntu 24.04 / Python 3.10 / CPU-only PyTorch + ONNX Runtime / 2 threads；真实 synthesis 与 audio sanity 全通过。
- CosyVoice offline preflight：WeText 5 个 FST 显式下载并生成 SHA-256 manifest；随后禁止 `snapshot_download()`，Adapter 仍可从本地 FST load model。
- 下一步仍需真实弱算力目标设备验证；若目标平台提供 cgroup/kernel OOM event，再增加平台特定确定归因。
