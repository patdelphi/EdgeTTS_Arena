# 项目实施计划与路线图

> 版本：v0.2 ｜ 采用 Stage 0~6，不以固定周数绑定实现

## 1. 总体路线

```text
Stage 0        Stage 1          Stage 2        Stage 3       Stage 4       Stage 5       Stage 6
Bootstrap  ->  Core Runtime ->  Adapters   ->  API       ->  Arena UI ->  Benchmark ->  Hardening
```

原则：每阶段都必须保持仓库可运行、测试可执行；尚未实现的真实模型使用 feature flag / placeholder，不阻塞主链路。

## 3. 不阻塞开发的占位策略

以下任务允许先提交结构和 placeholder：

- Qwen3-TTS 的最终 CPU runtime。
- CosyVoice / MeloTTS 真实接入。
- streaming 对不支持模型只做 capability gate。
- 硬件 affinity 在不支持平台跳过。

Placeholder 必须：

- 有明确 `NotImplementedError` 或 `status=unavailable`。
- 不伪造 benchmark 数据。
- 有 TODO/issue 对应后续 stage。

## 4. Stage Gate

每一阶段完成必须满足：

1. `pytest` 通过。
2. README / docs 状态同步。
3. 无新增未记录的接口破坏。
4. 运行示例可重复执行。
5. 新增模型不影响 Dummy baseline。

## 5. 风险

| 风险 | 策略 |
|---|---|
| 模型依赖冲突 | MVP 单环境；必要时 Phase 2 独立 venv worker |
| 大模型 OOM | lazy load、互斥常驻、ResourceGuard |
| CPU 争抢 | sequential 默认；concurrent 单独统计 |
| 不同平台 affinity 差异 | best-effort |
| 社区量化路线不可用 | feature flag + 官方运行时优先 |
| 文档性能值失真 | 所有性能以报告实测为准 |
