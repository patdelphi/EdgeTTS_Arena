## Qwen3 hosted baselines

- official FP32@2：RTF 5.315 / 5318MB。
- native INT8@2：RTF 1.787 / 3124MB。
- native INT8@4：RTF 1.984 / 3129MB。
- native INT4@4：RTF 2.432 / 2899MB。

当前选择：INT8@2；INT4 仅作为低内存实验项。相同 seed/text 下 INT4 与 INT8 时长不同，音质必须单独验证。

## Worker / OOM diagnostics

1. spawn 与 external worker 均保留 pid/exit/signal/elapsed/runtime diagnostics。
2. 显式 `MemoryError` / `worker_memory_error` → `worker_memory_error` evidence。
3. Linux cgroup v2：SIGKILL 且 `memory.events.oom_kill` 在执行窗口增加 → `cgroup_oom_kill_observed`。
4. SIGKILL 但没有上述证据 → `sigkill_suspected`，不宣称确定 OOM。
5. watchdog timeout 后 Arena 自己的 terminate/kill → `oom_classification=none`。
6. cgroup 计数是 cgroup-wide，因此 observed 仍保留审慎语义；Windows/macOS 可后续追加原生 evidence source。

## Extended bootstrap workflow

1. `bootstrap_extended_model.py MODEL --python PYTHON` 默认只输出计划。
2. `--execute` 才真正创建专用 venv、联网安装与下载模型。
3. profile 固定与 heavy gate 一致的 Python/runtime/source/model revision。
4. runtime preflight 后执行定向 `doctor --worker MODEL_ID`。
5. 输出 `bootstrap_plan.json`、`env.sh`、`env.ps1`。
6. MeloTTS/CosyVoice heavy gate 已复用相同 preparation helper，避免 CI 与本地流程漂移。
7. bootstrap success 与 real synthesis/target-device pass 分开标记。

## Quant quality workflow

1. `prepare_qwen3_native_variants.py` 生成匹配 INT8/INT4 manifests。
2. 默认 catalog 提供两个 disabled/experimental model ids。
3. Arena 多模型计算共同 voice/language 交集。
4. 固定同一 voice/language/seed 后生成两条音频。
5. Blind AB 匿名评分 Naturalness / Intelligibility / Prosody。
6. Reveal 后 `blind_scores.json` + benchmark report 一并归档。

## Target-device workflow

1. 在目标设备准备对应 runtime/model assets。
2. 用 `target_device_acceptance.py` 连续真实 synthesis。
3. 保存 environment + 每次 WAV/JSON + aggregate + ZIP。
4. 可限定 arch，并按最差 RTF/RSS 与目标 SLA 判定。
5. Qwen native 自动检查 `OPENBLAS_NUM_THREADS` 未预设。
