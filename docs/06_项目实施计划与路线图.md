# 项目实施计划与路线图

> 版本：v0.2 ｜ 采用 Stage 0~6，不以固定周数绑定实现  
> 当前进度：**Stage 0~4 已实现，下一阶段为 Stage 5 Benchmark Suite**

## 1. 总体路线

```text
Stage 0        Stage 1          Stage 2        Stage 3       Stage 4       Stage 5       Stage 6
Bootstrap  ->  Core Runtime ->  Adapters   ->  API       ->  Arena UI ->  Benchmark ->  Hardening
   ✅              ✅              ✅           ✅            ✅
```

原则：每阶段都必须保持仓库可运行、测试可执行；尚未实现的真实模型使用 feature flag / placeholder，不阻塞主链路。

## 3. 当前运行入口

纯 API：

```bash
edgetts-arena serve
```

Arena UI：

```bash
python -m pip install -e ".[ui]"
edgetts-arena serve --ui
```

UI 挂载在 `/arena/`，基础 API 保持原路径不变。

## 4. 不阻塞开发的占位策略

以下任务允许 placeholder：

- Qwen3-TTS 最终 CPU runtime。
- CosyVoice / MeloTTS 真实接入。
- 硬件 affinity 在不支持平台跳过。

Placeholder 必须：

- 明确 `NotImplementedError` 或 `status=unavailable`。
- 不伪造 benchmark 数据。
- 不伪造 capability。

## 5. Stage Gate

每一阶段完成必须满足：

1. `pytest` 通过。
2. README / docs 状态同步。
3. 无新增未记录接口破坏。
4. 运行示例可重复执行。
5. 新增模型/UI 不影响 Dummy/API baseline。
6. 可选依赖必须有独立 CI gate，不得强迫基础安装携带全部重依赖。

## 6. 风险

| 风险 | 策略 |
|---|---|
| 模型依赖冲突 | MVP 单环境；必要时 Phase 2 独立 venv worker |
| 大模型 OOM | lazy load、互斥常驻、ResourceGuard |
| CPU 争抢 | Sequential 默认；Concurrent 单独统计 |
| UI 依赖膨胀 | Gradio `[ui]` extra + 独立 CI |
| Blind 数据不可追溯 | mapping + ratings 写回 run artifact |
| 社区量化路线不可用 | feature flag + 官方运行时优先 |
| 文档性能值失真 | 所有性能以报告实测为准 |
