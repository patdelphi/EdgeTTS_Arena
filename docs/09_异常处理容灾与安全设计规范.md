# 异常处理、容灾与安全设计规范

> 版本：v0.2

## 1. ResourceGuard

### 1.1 内存保护

默认阈值通过配置提供，不硬编码到 Adapter：

```yaml
resource_guard:
  min_available_memory_mb_soft: 1536
  min_available_memory_mb_hard: 768
```

行为：

- Soft：禁止新的 concurrent 大模型任务，可尝试卸载闲置模型。
- Hard：拒绝启动新推理，HTTP 503 / app code 2002。

阈值是默认建议，弱算力设备可调整。

### 1.2 Timeout

timeout 按请求类型和模型配置决定，例如：

```yaml
inference_timeout_sec: 60
```

超时后：

1. 标记当前模型 result 为 error。
2. 终止/回收对应 worker。
3. 其他模型继续。
4. 非流式请求不宣称返回“局部完成音频”。流式模式只有已发送 chunk 可由客户端保留。

## 2. CPU 保护

- 默认线程数受控。
- 禁止 Adapter 直接把 `os.cpu_count()` 全量作为推理线程。
- OMP/MKL/OpenBLAS/PyTorch/ORT 线程配置统一。
- affinity best-effort；失败只记录 warning。

## 3. 输入安全

### 3.1 文本

- 默认最大 1000 字符，可配置。
- 清理 NUL/非法控制字符。
- Unicode 正规化。
- 长文本分句应有最大 chunk 长度和最大 chunk 数量。

### 3.2 路径

模型路径和导出下载接口必须防止 path traversal：

- 禁止客户端传绝对文件路径。
- 下载 filename 只允许安全 basename。
- resolve 后必须仍在 exports 根目录内。

## 4. 错误码

| Code | HTTP | 含义 | 处理 |
|---:|---:|---|---|
| 1001 | 400 | 输入无效 | 修正请求 |
| 1002 | 404 | 模型不存在/不可用 | 检查配置/模型 |
| 1003 | 409 | capability 冲突 | 调整参数 |
| 2001 | 503 | CPU/资源过载 | 稍后或 Sequential |
| 2002 | 503 | 内存保护触发 | 卸载模型/降低并发 |
| 3001 | 504 | 推理超时 | 回收 worker |
| 3002 | 500 | 模型内部错误 | 记录 traceback/ref id |

## 5. 进程故障隔离

- Web/API 主进程不得直接承载不可控重模型生命周期。
- worker 退出后 ModelRegistry 更新状态。
- 下一次请求可按配置决定是否自动重建一次；禁止无限自动重试。
- 记录 request/run/model id，便于排障。

## 6. 本地应用安全边界

MVP 默认面向本地可信环境，但仍需：

- 绑定 `127.0.0.1` 作为默认 host。
- 若用户显式绑定 `0.0.0.0`，启动日志给出暴露提示。
- 不提供任意 shell command API。
- 模型下载/执行路径不得由未校验 Web 参数直接控制。
