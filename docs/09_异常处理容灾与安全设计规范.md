# 异常处理、容灾与安全设计规范

> 版本：v0.3 ｜ Stage 6 hardening in progress

## 1. ResourceGuard

默认配置：

```yaml
resource_guard:
  min_available_memory_mb_soft: 1536
  min_available_memory_mb_hard: 768
  min_available_memory_mb_per_concurrent_model: 512
  max_concurrent_models: 4
```

Hard 阈值以下拒绝新任务（2002）。Soft 阈值以下禁止 Concurrent（2001）。

### Concurrent 预算

Concurrent 在创建线程池前必须完成资源计划：

- 模型数不得超过 `max_concurrent_models`。
- 可用内存至少满足 `max(soft_threshold, model_count × min_memory_per_concurrent_model)`。
- 每模型线程数最多为 `logical_cores // model_count`，防止 CPU 线程超配。
- 自动下调线程时记录 resource warning。
- 报告必须标记 `execution_profile=pressure`；Sequential 标记 `baseline`。

## 2. Timeout / worker

`inference_timeout_sec` 默认 60。Stage 1 已有可 terminate/kill 的 ProcessRunner；Stage 6 下一步将其接入真实 benchmark worker 主链路。完成接入前，不得宣称主 BenchmarkService 已具备进程级硬 timeout。

## 3. 输入与路径安全

文本限制、Unicode 正规化、下载 basename allow-list、exports root containment 保持启用。不得提供任意 shell command API。

## 4. 错误码

| Code | HTTP | 含义 |
|---:|---:|---|
| 1001 | 400 | 输入无效 |
| 1002 | 404 | 模型不存在/不可用 |
| 1003 | 409 | capability 冲突 |
| 2001 | 503 | CPU/并发/资源预算不足 |
| 2002 | 503 | hard memory guard |
| 3001 | 504 | 推理超时 |
| 3002 | 500 | 模型/worker 内部错误 |

## 5. 本地应用安全边界

默认绑定 `127.0.0.1`；显式绑定 `0.0.0.0` / `::` 时必须提示网络暴露风险。
