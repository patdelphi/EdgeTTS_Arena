# 异常处理、容灾与安全设计规范

> 版本：v0.3 ｜ Stage 6 watchdog 实现口径

## 1. ResourceGuard

默认阈值通过配置提供，不硬编码到 Adapter：

```yaml
resource_guard:
  min_available_memory_mb_soft: 1536
  min_available_memory_mb_hard: 768
  min_available_memory_mb_per_concurrent_model: 512
  max_concurrent_models: 4
```

- Soft：Sequential 可继续但记录 warning；Concurrent 不满足预算时拒绝启动。
- Hard：拒绝新推理，HTTP 503 / app code `2002`。
- Concurrent 同时受最大模型数、每模型最低内存预算和逻辑核公平线程预算约束。

## 2. 进程级 Watchdog

默认超时配置：

```yaml
inference_timeout_sec: 60
```

`BenchmarkService` 与 `RepeatedBenchmarkService` 默认创建 `spawn` 进程 runner；嵌入式调用或测试如需保留进程内语义，可显式传入 `isolate_model_processes=False`。

### 2.1 非持久模型

`keep_in_memory=false` 的模型默认使用 `spawn` 子进程：

1. 主进程校验 capability、run_id、模型配置和目标 WAV 路径。
2. worker 执行 load → infer → metrics → WAV write → unload。
3. WAV 直接写入预先校验的 `exports/<run_id>/audio/`，不通过 multiprocessing queue 复制大音频。
4. queue 仅回传 metrics、metadata 和 error 小对象。
5. 单轮超过 `inference_timeout_sec` 时 terminate，必要时 kill，返回 `3001 inference_timeout`。
6. worker 异常退出或没有返回结果时返回 `3002 worker_exited`，其他模型和 API 主进程继续。
7. worker 结束后 Registry 状态恢复为 `unloaded`。

### 2.2 Standard Suite

Suite 采用一个 `case/model` 一个 worker group：

- worker 内完成 warm-up + measured repeats，避免每次 repeat 重复加载模型。
- group hard timeout 为 `inference_timeout_sec × max(1, warmup_runs + measured_runs)`。
- 只保存第一条成功 measurement 的代表 WAV，全部 raw measurements 仍写入 report。
- timeout/crash 只使当前 case/model 结果失败，不终止整个 Suite。

### 2.3 常驻模型边界

`keep_in_memory=true` 当前仍使用进程内执行，以保留常驻模型语义。此路径必须返回明确 warning：hard process timeout 尚未覆盖。不得把线程级超时伪装成可强杀的 worker 隔离。

## 3. OOM 边界

- Python worker 内可捕获的 `MemoryError` 映射为 `2002 worker_memory_error`。
- 操作系统直接 OOM-kill 当前只能表现为异常 worker exit（`3002`）；精确识别 cgroup/OS OOM 原因仍属于 Stage 6 后续工作。
- 不做无限自动重试。故障后的下一请求可以重新创建非持久 worker。

## 4. CPU 与并发保护

- Sequential 使用 baseline profile。
- Concurrent 使用 pressure profile，不与 baseline 性能排名混用。
- Concurrent 自动按逻辑核数计算公平 threads/model，保证总线程预算不超过可用逻辑核。
- affinity 仍是 best-effort，不作为跨平台正确性的前置条件。

## 5. 输入与路径安全

- 文本默认最大 1000 字符，拒绝非法控制字符并进行 Unicode 正规化。
- Web 请求不得直接提供任意本地模型路径或可执行命令。
- audio/export 使用 allow-list run_id 与安全 basename，resolve 后必须位于 export root。
- worker 的 `model_path` 来自受控模型配置，`audio_path` 来自主进程 `RunArtifactStore` 预校验。

## 6. 错误码

| Code | HTTP | 含义 |
|---:|---:|---|
| 1001 | 400 | 输入无效 |
| 1002 | 404 | 模型/run 不存在或不可用 |
| 1003 | 409 | capability 冲突 |
| 2001 | 503 | CPU/并发/资源预算不足 |
| 2002 | 503 | 内存保护或可捕获 MemoryError |
| 3001 | 504 | hard inference timeout |
| 3002 | 500 | 模型内部错误或 worker 异常退出 |

## 7. 本地应用安全边界

- 默认绑定 `127.0.0.1`。
- 显式绑定 `0.0.0.0` / `::` 时记录网络暴露 warning。
- 不提供任意 shell command API。
- 模型下载、执行路径和 worker 目标均不得由未校验 Web 参数直接控制。
