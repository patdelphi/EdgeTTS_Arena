# 前端 UI 交互原型与界面流程设计

> 版本：v0.2 ｜ UI 必须由后端 capability 驱动

## 1. 页面结构

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ EdgeTTS-Arena                       CPU / RAM / Runtime status            │
├─────────────────────────────┬────────────────────────────────────────────┤
│ 输入与配置                  │ Arena Results                              │
│ Preset                      │ Model A/B/C cards                          │
│ Text                        │ Audio player / waveform                    │
│ Models (2~4)                │ RTF / RSS / CPU / TTFB                     │
│ Execution: Sequential       │ Warning / Error                            │
│ Threads                     │                                            │
│ Voice / Speed / Seed        │                                            │
│ [Run Benchmark]             │                                            │
├─────────────────────────────┴────────────────────────────────────────────┤
│ Comparison Table / Blind AB / Export                                   │
└──────────────────────────────────────────────────────────────────────────┘
```

## 2. 初始化流程

页面加载后首先调用：

`GET /api/v1/system/models`

根据返回内容构建：

- 模型可选状态。
- `ready/unavailable/error` 标识。
- voices。
- languages。
- streaming/seed/speed 等 capability。

不得在前端硬编码“某模型一定支持某参数”。

## 3. 参数联动

- 所有已选模型都支持 speed：显示 speed slider。
- 任一模型不支持 seed：可隐藏 seed，或标记“仅部分模型生效”并在提交前拆分参数。
- streaming 只在单模型且 `streaming=true` 时开放实时播放模式。
- voice 列表随当前模型切换；多模型 Arena 可允许每模型独立 voice。

## 4. Benchmark 流程

```text
选择 Preset / 输入文本
        ↓
选择 1~4 模型与执行模式
        ↓
Capability validation
        ↓
POST /api/v1/benchmark/run
        ↓
同步等待最终结果（MVP）
        ↓
逐模型展示 success/error + audio + metrics
        ↓
可导出 ZIP
```

MVP 不需要对同步 `/benchmark/run` 做假异步轮询。

## 5. Arena 卡片

每个模型卡片展示：

- model display name / status。
- audio player。
- inference time / audio duration / RTF。
- peak RSS / RSS delta / avg CPU。
- TTFB：`null` 时显示 `N/A (non-streaming)`。
- warnings。
- error message（若失败）。

不得用固定阈值把 RTF 标成“极佳/良好”等绝对判断；可后续基于用户配置的 benchmark target 做相对状态。

## 6. Blind AB

1. 生成结果后可进入 Blind 模式。
2. 模型 ID 映射为随机匿名标签。
3. 播放顺序随机化。
4. 评分：Naturalness / Intelligibility / Prosody，1~5。
5. 提交后揭晓模型。
6. 保存匿名映射、评分、run_id，保证可追溯。

## 7. 错误与降级

- 单模型失败：其他卡片照常展示。
- 内存保护：明确提示资源不足，不自动无限重试。
- unsupported capability：提交前拦截。
- streaming 不支持：退回整段生成模式，不伪造流式进度。

## 8. MVP 与后续

MVP：Gradio 可以作为最快的 UI 实现。若后续需要更复杂的流式播放器、波形或大规模 Blind 数据管理，可再迁移/增加独立 Web 前端；API 契约保持不变。
