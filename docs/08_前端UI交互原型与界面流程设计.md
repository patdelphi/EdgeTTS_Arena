# 前端 UI 交互原型与界面流程设计

> 版本：v0.3 ｜ Stage 4 MVP 已实现 ｜ UI 必须由 runtime capability 驱动

## 1. 实现方式

MVP 使用 **Gradio 6.x** 作为可选 UI 层，通过 `gradio.mount_gradio_app()` 挂载到 Stage 3 FastAPI 的 `/arena`。

```bash
python -m pip install -e ".[ui]"
edgetts-arena serve --ui
```

打开 `http://127.0.0.1:8000/arena/`。

设计约束：

- Gradio 不是基础依赖；纯 API 模式 `edgetts-arena serve` 不需要安装 Gradio。
- UI 与 API 运行在同一进程，共享同一 `ModelRegistry`、`BenchmarkService` 与 `RunArtifactStore`。
- 外部前端仍使用 Stage 3 API；挂载式 Gradio MVP 不做无意义的本机 HTTP 自调用，而直接使用同一业务服务层。
- Gradio 只允许读取 export root，避免任意本地路径暴露。

## 2. 页面结构

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ EdgeTTS-Arena                         OS / cores / RAM                   │
├──────────────────────────────────────────────────────────────────────────┤
│ Runtime model status table + Refresh                                   │
├─────────────────────────────┬────────────────────────────────────────────┤
│ 输入与配置                  │ Run summary / Export ZIP                  │
│ Text                        │                                            │
│ Models 1~4                  │                                            │
│ Sequential / Concurrent     │                                            │
│ Threads                     │                                            │
│ Speed / Seed / Voice        │                                            │
│ Capability summary          │                                            │
│ [Run benchmark]             │                                            │
├─────────────────────────────┴────────────────────────────────────────────┤
│ Arena Results: up to 4 audio players + metric cards                    │
│ Comparison Table                                                        │
├──────────────────────────────────────────────────────────────────────────┤
│ Blind AB: anonymous audio → 3-axis score → reveal                      │
└──────────────────────────────────────────────────────────────────────────┘
```

Arena 横向评测建议选 2~4 模型；UI 同时允许单模型运行，便于调试和真实模型安装验证。

## 3. 初始化与状态刷新

页面初始化与 Refresh 都从 runtime 重新读取：

- 模型 ID / display name。
- `unloaded / ready / busy / unavailable / error` 状态。
- experimental 标识。
- voices / languages。
- streaming / seed / speed / voices / voice_clone capability。
- OS / arch / CPU core / RAM。

前端不得硬编码“Piper 一定支持 X”或“Kokoro 一定支持 Y”。

## 4. 参数 capability 联动

当前 MVP 规则：

- **Speed**：只有所有已选模型都声明 `speed=true` 时启用；UI 使用当前已验证模型共同安全范围 `0.5~2.0`。
- **Seed**：至少一个已选模型支持时启用；若只是部分支持，界面明确显示 partial support，后端对不支持模型记录 warning，不静默伪装 deterministic。
- **Voice**：单模型且有 voice 列表时启用；多模型 Arena 自动让每个 Adapter 使用自己的默认 voice，避免把同一个 voice id 错套到多个模型。
- **Streaming**：UI 显示单模型是否具备 streaming capability；真实 streaming 通道继续由 Stage 3 WebSocket 提供。MVP Arena 主按钮仍使用同步 benchmark，以保证横向指标语义一致。
- **Concurrent**：可选但不是默认；仍受 ResourceGuard 内存保护，压力测试与 Sequential 报告语义不得混淆。

## 5. Benchmark 流程

```text
输入文本
  ↓
选择 1~4 模型
  ↓
Capability-driven 控件
  ↓
选择 Sequential / Concurrent + threads
  ↓
Run benchmark
  ↓
BenchmarkService 同步返回最终结果
  ↓
逐模型 audio + metrics + warning/error
  ↓
Comparison Table
  ↓
Export ZIP / Blind AB
```

UI 不对同步 `/benchmark/run` 做假异步轮询。

## 6. Arena 结果卡

每个结果卡展示：

- model display name。
- success / error。
- audio player。
- inference time。
- audio duration。
- RTF。
- peak RSS。
- RSS delta。
- avg CPU usage。
- TTFB。
- warnings / error。

`ttfb_ms=null` 必须显示：

```text
N/A (non-streaming)
```

不允许用整段生成耗时伪造 TTFB，也不使用固定阈值把 RTF 标为“优秀/差”。

## 7. Blind AB MVP

Blind AB 已实现：

1. 只有一轮至少 **2 个 successful result** 时才可启动。
2. 只纳入成功模型；失败模型不进入盲测。
3. 使用系统随机源重新打乱模型顺序。
4. 模型映射为 Sample A/B/C/D；揭晓前 session 中不暴露单独 `mapping` 字段。
5. 用户对每个匿名 sample 评分：
   - Naturalness：1~5
   - Intelligibility：1~5
   - Prosody：1~5
6. 所有 sample 都评分完成后才允许 Reveal。
7. Reveal 后显示匿名 label → model_id 映射及评分。
8. 同时写入：

```text
exports/<run_id>/blind_scores.json
```

9. 重新构建 ZIP，Blind 数据与 WAV、benchmark report、environment snapshot 一起归档。

这样 Blind 结果与 `run_id` 一一对应，可追溯而不是只保存在浏览器状态。

## 8. 错误与降级

- 单模型失败：其他卡片正常显示。
- unavailable 模型：状态表明确显示；若用户仍选择，结果按单模型 error 隔离。
- 内存保护：直接展示 ResourceGuard 错误，不无限重试。
- unsupported capability：UI 尽量提前禁用；服务层仍做最终校验。
- 多模型 voice：退回各模型 default，而不是猜测 voice 映射。
- Gradio 未安装：纯 API 正常工作；只有 `serve --ui` 需要 `[ui]` extra。

## 9. CI Gate

Stage 4 增加独立 `ui-smoke` job：

- Python 3.11。
- 安装 `.[dev,ui]`。
- presenter / Blind AB 纯逻辑测试。
- Gradio `Blocks` 配置构建。
- Gradio 挂载 Stage 3 FastAPI 后 `/healthz` 和 `/arena/` 同时可访问。

普通 Python 3.10~3.12 测试不强制安装 Gradio，保持 UI 的可选依赖边界。

## 10. 后续

Stage 5 重点不再扩 UI 花样，而是补齐 benchmark suite：preset、warm-up、repeated runs、统计汇总和完整复现报告。后续若需要更复杂的实时波形、WebSocket 播放或大规模 Blind 数据管理，再增加独立 Web frontend；Stage 3 API 契约保持稳定。
