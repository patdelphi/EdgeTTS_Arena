## 本地部署 Ready

**主 Arena 已满足本地部署测试工程判定，现在可以开始本地部署测试。** 该判定基于跨平台 Doctor、Python 3.10~3.12、UI/API/spawn smoke、Piper/Kokoro 真实 CPU gate 等持续 CI 证据；扩展模型仍默认 experimental/disabled。

扩展模型 bootstrap 属于工程 ready：可以生成与 heavy gate 对齐的专用环境并做 Worker Doctor，但 **bootstrap 成功仍不等于真实模型 synthesis gate 或目标设备性能 gate 已通过**。

## OOM 诊断边界

- `worker_memory_error` 是应用层直接证据。
- `cgroup_oom_kill_observed` 要求 SIGKILL 与执行窗口内 cgroup v2 `memory.events: oom_kill` 增量同时出现；该计数属于整个 cgroup，因此不写成“确定该 PID OOM”。
- `sigkill_suspected` 只表示疑似 OOM 或外部 kill。
- timeout watchdog 自己发出的 kill 不参与 OOM 推断。
- Windows/macOS 当前没有伪造 Linux cgroup 证据；未来可按平台增加原生证据源，但不是主 Arena 本地部署 blocker。

## 其他边界

量化性能 route、Blind AB harness、目标设备验收工具和扩展模型 bootstrap 都已完成，但：

- harness ready 不等于 quality verified；
- target-device harness ready 不等于真实硬件已经 verified；
- hosted ARM64/1-CPU smoke 不等于树莓派/目标设备性能结论；
- bootstrap/Doctor ready 不等于对应重模型已经在该本机完成真实 synthesis。
