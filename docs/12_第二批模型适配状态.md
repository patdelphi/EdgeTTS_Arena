### 首次 Qwen3 hosted FP32 baseline

GitHub Actions run `33761262528`，GitHub-hosted Ubuntu x86_64，Python 3.11，`qwen-tts==0.1.1`，CPU-only PyTorch，2 threads，Vivian，language=Auto：

| 指标 | 结果 |
|---|---:|
| Sample rate | 24000 Hz |
| Audio duration | 9.04 s |
| Inference time | 48.05 s |
| RTF | 5.315 |
| Peak RSS | 5317.8 MB |
| Inference RSS delta | 862.3 MB |
| Average process CPU | ~200% |
| Peak amplitude | 0.803 |
| RMS | 0.1065 |

WAV finite、非静音、时长合理，真实 synthesis gate 通过。该结果证明官方 FP32 CPU runtime 可工作，但约 5.3GB peak RSS 与 RTF 5.3 不符合 EdgeTTS-Arena 的端侧优化目标，因此 FP32 保留为官方兼容/功能基线，不作为最终弱设备推荐路线。

## 独立 Python / venv Worker

主 Arena 不要求把扩展模型依赖直接安装到 UI venv。`ModelSpec` 支持：

```yaml
worker_python: ""
worker_python_env: EDGETTS_ARENA_QWEN3_PYTHON
```

优先级：显式 `worker_python` > `worker_python_env` 环境变量 > 当前 Python 的普通 `spawn` worker。

默认环境变量：

```text
EDGETTS_ARENA_QWEN3_PYTHON
EDGETTS_ARENA_COSYVOICE_PYTHON
EDGETTS_ARENA_MELOTTS_PYTHON
```

external worker 使用版本化 JSON stdin/stdout 协议调用 `edgetts_arena.core.external_worker`，沿用 hard timeout、terminate/kill 与 PID/exit/signal/elapsed/oom_suspected 诊断。

`doctor --workers` 检查全部声明的专用解释器；`doctor --worker MODEL_ID` 可只检查一个或多个指定模型。两者都只执行 Dummy WAV protocol probe，**不等价于真实模型 synthesis gate**。
