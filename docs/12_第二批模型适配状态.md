## 独立 Python / venv Worker

主 Arena 不再要求把 CosyVoice/MeloTTS 的依赖直接安装到 UI venv。`ModelSpec` 支持：

```yaml
worker_python: ""
worker_python_env: EDGETTS_ARENA_COSYVOICE_PYTHON
```

优先级：显式 `worker_python` > `worker_python_env` 对应环境变量 > 当前 Python 的普通 `spawn` worker。

默认环境变量：

```text
EDGETTS_ARENA_COSYVOICE_PYTHON
EDGETTS_ARENA_MELOTTS_PYTHON
```

Linux/macOS 示例：

```bash
export EDGETTS_ARENA_COSYVOICE_PYTHON="$PWD/.venv-cosyvoice/bin/python"
export EDGETTS_ARENA_MELOTTS_PYTHON="$PWD/.venv-melotts/bin/python"
edgetts-arena doctor --workers
```

Windows PowerShell 示例：

```powershell
$env:EDGETTS_ARENA_COSYVOICE_PYTHON = (Resolve-Path .venv-cosyvoice\Scripts\python.exe)
$env:EDGETTS_ARENA_MELOTTS_PYTHON = (Resolve-Path .venv-melotts\Scripts\python.exe)
edgetts-arena doctor --workers
```

external worker 使用 JSON stdin/stdout 协议调用 `edgetts_arena.core.external_worker`，并沿用 hard timeout、terminate/kill、PID/exit/signal/elapsed/oom_suspected 诊断。主进程只接收小型 JSON metadata，WAV 由 worker 写入主进程预先校验的 artifact 路径。

`doctor --workers` 会用每个已声明的专用解释器执行 Dummy WAV probe，用于检查 Python 可启动、项目 source 可导入、基础 worker 依赖与协议可工作。它**不等价于模型 synthesis gate**；真实模型依赖、模型资产和模型推理仍需各自 smoke/gate 验证。

Worker venv 至少需要 external worker 路径涉及的基础依赖（如 NumPy、SoundFile、psutil、PyYAML）以及对应模型运行时依赖。项目 source 由主 Arena 在启动 worker 时通过 `PYTHONPATH` 注入，因此无需把 CosyVoice/MeloTTS 的旧依赖合并到主 UI venv。

## Gate 原则

在以下条件全部满足前，不把扩展模型默认标记为正式可用：

1. 可复现本地模型包。
2. Python/runtime 依赖使用专用 venv worker，或已证明与主环境兼容。
3. CPU 输出 WAV 非空且 metadata/RTF 可记录。
4. 许可证和模型许可可追溯。
5. CI/目标设备真实 synthesis 通过。

当前 1~4 已满足，x86_64 hosted real CPU gate 已满足；真实目标弱设备仍是 Stage 6 剩余验证项，因此两模型继续保持默认 disabled/experimental。
